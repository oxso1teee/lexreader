## 0. TL;DR — что делать в первую очередь

Если читать только этот раздел:

1. **Баг**: `markKnown` в Тетради не синхронизирует `level` — слово помеченное "знаю" в Тетради не подсвечивается зелёным/серым в читалке и не считается выученным в статистике по уровню.
2. **Твоя любимая фича не работает так, как ты её описал**: YouTube-импорт сейчас = текст без видео. Нужен режим "смотреть + читать субтитры синхронно + тапать слова" — это отдельная функция, ниже полная спека (раздел 3).
3. **Настройки профиля не редактируются** — только просмотр. Нельзя сменить изучаемый язык, уровень, цель в день после онбординга.
4. **В библиотеке текстов нет**: удаления, процента прочтения, даты последнего чтения, оценки времени чтения — всё это было в исходном ТЗ и в скриншотах референса, но не реализовано.
5. **Мозг (колоды) никак не ограничен бесплатным тарифом** — при этом Тетрадь ограничена. Нужно решить осознанно, а не оставлять как случайность.
6. **Learning steps (минуты) в Study Settings хранятся, но не используются** — SM-2 движок их игнорирует. Либо реализовать по-настоящему, либо явно убрать эти поля из UI, чтобы не врать пользователю.
7. **Ручное добавление слова в Тетрадь без текста-источника** — было в исходном ТЗ (раздел 4.4), не реализовано.
8. **Мобильный long-press может конфликтовать со скроллом/выделением текста** — не установлен `touch-action`/`user-select`, на реальном телефоне может работать не так, как в тестах на десктопе.

## 1. Критические баги (чинить в первую очередь)

### 1.1 `status` и `level` у слова рассинхронизированы

Файл: `src/app/(app)/notebook/actions.ts`, функция `markKnown`:

```ts
export async function markKnown(id: string) {
  const supabase = await createClient();
  const { error } = await supabase
    .from("vocabulary_items")
    .update({ status: "known" })   // ← обновляет только status
    .eq("id", id);
  ...
}
```

А в читалке (`src/app/read/[textId]/reader.tsx`, `handleSetLevel`) обновляются **оба** поля синхронно (`level` + `status` через `setWordLevel`). Получается два независимых источника правды:

- Пометил "Уже знаю" в Тетради → `status='known'`, но `level` остался как было (например 0) → в читалке слово всё ещё подсвечено оранжевым "New", хотя в Тетради оно "Выучено".
- Статистика на `/progress` считает "Знаю (ур. 4)" по `status='known'` — тут совпадёт. Но карточка легенды/подсветки в читалке использует `level`, а не `status` — не совпадёт.

**Что делать**: сделать `markKnown` устанавливать `level=4` одновременно со `status='known'` (как в `setWordLevel`). Правильнее всего — вынести общую функцию `syncStatusAndLevel` в `src/lib/word-level.ts` и использовать её в обоих местах (`notebook/actions.ts` и `read/[textId]/actions.ts`), чтобы не разъезжались снова при следующей правке.

### 1.2 Мобильный long-press — нет `touch-action`/`user-select`

Файл: `src/app/read/[textId]/reader.tsx`, кнопки слов.

Сейчас: `onPointerDown/onPointerEnter/onPointerUp` без `style={{ touchAction: 'none', userSelect: 'none' }}` и без `-webkit-user-select: none`. На реальном телефоне при удержании пальца браузер может: (а) начать нативное выделение текста, (б) проскроллить страницу, (в) показать контекстное меню "Скопировать/Поделиться" — что перебьёт наш JS-обработчик выделения фразы.

**Что делать**: добавить на кнопки слов `className="... touch-none select-none"` (Tailwind: `touch-none` → `touch-action: none`, `select-none` → `user-select: none`), и протестировать на настоящем мобильном устройстве или хотя бы в Chrome DevTools с эмуляцией touch + throttling.

### 1.3 Многосентенсный phrase-select не поддерживается

Файл: `reader.tsx`, `onPointerEnterWord` — проверяет `sel.si === si` (тот же индекс предложения). Если пользователь начинает long-press в конце одного предложения и тянет палец в начало следующего — выделение просто не расширяется за границу предложения, без предупреждения (тихо режет диапазон).

**Что делать (по приоритету)**:
- Минимум: показать лёгкую визуальную границу/тост "Фразу можно выделить только в пределах одного предложения" при попытке выйти за границу.
- Лучше: разрешить выделение через границы предложений — потребует хранить глобальный плоский индекс токена по всему телу текста, а не (si, ti) пару. Это рефакторинг токенизации, но не критичный для MVP.

## 2. Настройки профиля — сделать редактируемыми

Файл: `src/app/(app)/settings/settings-client.tsx` — сейчас блок "Профиль" это просто `<dl>/<dd>` только для чтения:

```tsx
<dl className="grid grid-cols-2 gap-y-1 text-sm">
  <dt>Изучаю</dt><dd>{targetLanguage}</dd>
  ...
```

Ни изучаемый язык, ни родной, ни уровень, ни цель в день **нельзя изменить** после онбординга. Это прямое требование исходного ТЗ (раздел 4.7: "Профиль, языки (изучаемый/родной), цель в день").

**Что реализовать**:
1. Server action `updateProfile(formData)` в `src/app/(app)/settings/actions.ts`:
   ```ts
   export async function updateProfile(_prevState, formData) {
     const supabase = await createClient();
     const profile = await requireProfile();
     const targetLanguage = String(formData.get("target_language"));
     const nativeLanguage = String(formData.get("native_language"));
     if (targetLanguage === nativeLanguage) return { error: "Языки должны отличаться" };
     const level = String(formData.get("level") || "") || null;
     const dailyWordGoal = Number(formData.get("daily_word_goal"));
     const { error } = await supabase.from("profiles").update({
       target_language: targetLanguage,
       native_language: nativeLanguage,
       level,
       daily_word_goal: dailyWordGoal,
     }).eq("id", profile.id);
     if (error) return { error: error.message };
     revalidatePath("/settings");
     revalidatePath("/home");
     return { saved: true };
   }
   ```
2. В `SettingsClient` заменить `<dl>` на форму: селект языка (переиспользовать `LANGUAGES` из `src/lib/languages.ts`, с исключением одинакового значения для второго селекта — как в онбординге), селект уровня (те же 3 значения, что в онбординге: beginner/intermediate/advanced), слайдер/кнопки цели в день (5/10/20/30 — переиспользовать тот же список констант, что в `onboarding-wizard.tsx`, лучше вынести в общий `src/lib/onboarding-options.ts`, чтобы не дублировать).
3. **Важный побочный эффект**: смена `target_language` меняет язык, для которого показывается библиотека (`library/page.tsx` фильтрует `.eq("language", profile.target_language)`) — значит все существующие тексты и слова для СТАРОГО языка станут невидимы в библиотеке/читалке (они никуда не денутся из БД, просто отфильтруются). Нужно либо предупредить пользователя об этом в UI ("Тексты и слова для другого языка останутся в базе, но не будут видны, пока не переключишься обратно"), либо (лучше на будущее) поддержать несколько активных языков одновременно — это отдельная архитектурная задача, см. раздел 8.

## 3. YouTube "Watch Mode" — видео + синхронные субтитры + тап-в-карточку

Это твоя любимая часть, разворачиваю подробно.

### 3.1 Что есть сейчас

`src/app/(app)/library/youtube-actions.ts` → `createTextFromYoutube`:
- Парсит `videoId` из ссылки.
- Скачивает HTML страницы просмотра, регуляркой достаёт `captionTracks` (неофициальный способ — может сломаться при изменении вёрстки YouTube).
- Скачивает XML/timedtext по `baseUrl`, **выбрасывает все таймкоды**, склеивает голый текст через пробел.
- Сохраняет как обычный `texts` row (`source_type='youtube'`).
- Дальше это открывается в ТОЙ ЖЕ читалке, что и любой другой текст — без видео, без синхронизации, без возможности слушать.

### 3.2 Чего хочет пользователь (пересказ запроса)

> "можно смотреть и снизу читать субтитры и нажимать на слова и в карточки их и перевод"

То есть:
1. Видео проигрывается (embed).
2. Под видео — текущая строка субтитров, синхронизированная с плеером по времени.
3. Тап по слову в этой строке → перевод в контексте (как в обычной читалке) → сохранить как карточку.
4. Судя по всему, ожидается что можно листать/останавливаться на нужном моменте, а не просто разово прочитать транскрипт целиком.

### 3.3 Архитектура решения

**Модель данных** — новая миграция `0006_youtube_captions.sql`:

```sql
alter table texts add column youtube_video_id text;

create table caption_segments (
  id uuid primary key default gen_random_uuid(),
  text_id uuid not null references texts(id) on delete cascade,
  start_ms int not null,
  end_ms int not null,
  body text not null,
  segment_index int not null
);
create index caption_segments_text_idx on caption_segments (text_id, segment_index);
alter table caption_segments enable row level security;
create policy "caption_segments: read via owning text" on caption_segments
  for select using (
    exists (select 1 from texts t where t.id = caption_segments.text_id
      and (t.owner_id = auth.uid() or t.owner_id is null))
  );
grant select, insert on caption_segments to authenticated;
-- insert ограничить владельцем текста через сервер-экшен (RLS insert policy аналогично select, but with check on owner_id match)
```

(Свериться с существующим паттерном RLS в `0001_init.sql`/`0004_decks.sql` при реализации — там уже есть шаблон "owner via join".)

**Импорт** — переписать `createTextFromYoutube`:
- НЕ выбрасывать таймкоды. Парсить timedtext XML в массив `{ startMs, endMs, body }` (атрибуты `start`/`dur` в XML, переводим в мс).
- Сохранить `texts.youtube_video_id = videoId`, `texts.source_type='youtube'`.
- Вставить все сегменты в `caption_segments` (bulk insert).
- `texts.body` — можно оставить как склеенный текст (для fallback/для статистики уникальных слов на `/read`), но реальный рендеринг видео-режима работает через `caption_segments`, не через `body`.

**Экран** — новый роут `src/app/(app)/watch/[textId]/page.tsx` + `watch-player.tsx` (client):
- Если `texts.youtube_video_id` есть → кнопка "Смотреть" на карточке текста в библиотеке ведёт на `/watch/[id]` вместо `/read/[id]` (обычная читалка `/read/[id]` при этом всё равно доступна для того, кто хочет просто прочитать транскрипт целиком, без видео — оставить обе точки входа).
- Верстка: YouTube IFrame Player API (`https://www.youtube.com/iframe_api`, официальный, бесплатный, без ключа для встраивания) сверху, под ним — блок с ТЕКУЩИМ сегментом субтитров, токенизированным как в читалке (переиспользовать `src/lib/tokenize.ts` + ту же tap-to-translate логику из `reader.tsx`, лучше вынести общий `<TappableText tokens={...} onWordTap={...} />` компонент, которым пользуются и `/read`, и `/watch`).
- Слушать `player.getCurrentTime()` через `setInterval` (250-500мс) или через YouTube Player API's `onStateChange`/timeupdate-подобный polling (у YouTube IFrame API нет нативного timeupdate-события, только polling через `getCurrentTime()` — это стандартная практика для такого рода приложений), находить активный сегмент (`startMs <= t*1000 < endMs`), подсвечивать его, автоскроллить к нему список сегментов (показывать окно ±2 сегмента вокруг текущего, чтобы видно было контекст до/после — как обычно в приложениях-плеерах с субтитрами).
- Тап по слову в активном сегменте → тот же попап, что в читалке (перевод + сохранение в Тетрадь), можно также разрешить тап по словам в СОСЕДНИХ (неактивных) видимых сегментах.
- Клик по сегменту (не по слову, а по всей строке) → `player.seekTo(startMs/1000)` — перескочить видео на этот момент (стандартное поведение "кликни по субтитру → перемотай").
- Кнопки паузы/play можно оставить нативные YouTube-плеера (iframe уже их рисует), плюс, может быть, свою кнопку "⏮ Повторить фразу" (перемотать на `startMs` текущего сегмента и продолжить).

**Ограничения, о которых нужно честно предупредить пользователя в UI** (уже частично есть в форме импорта, дополнить):
- Работает только для видео с открытыми субтитрами (уже есть предупреждение).
- Парсинг HTML-страницы YouTube — неофициальный способ, может сломаться при изменении вёрстки YouTube в любой момент без предупреждения. Официальный YouTube Data API v3 требует OAuth и не даёт скачивать субтитры чужого видео без разрешения владельца — поэтому либо мириться с хрупкостью неофициального метода, либо ограничить импорт только СВОИМИ видео пользователя через официальный API (сложнее в реализации, требует Google OAuth настройки — отдельная задача).
- Если YouTube отдаёт **автоматически сгенерированные** субтитры (ASR), сегменты могут быть неточными по границам слов/предложений — это нормально, не баг, но стоит показать маленькую пометку "автоматические субтитры" если тип трека это позволяет определить (в `captionTracks` JSON обычно есть поле `kind: "asr"` — можно проверить и сохранить, показать бейдж).

**Порядок реализации**:
1. Миграция `caption_segments` + `texts.youtube_video_id`.
2. Переписать импорт-парсинг (сохранять таймкоды).
3. Общий `<TappableText>` компонент (рефакторинг существующей токенизации из `reader.tsx` в переиспользуемый кусок — не обязательно быстро, но так проще поддерживать одну логику тапа в двух местах).
4. `/watch/[textId]` — плеер + текущий сегмент + тап-перевод.
5. В библиотеке — показывать иконку/бейдж "📺" на карточках с `youtube_video_id`, кнопка "Смотреть" рядом с обычным открытием текста.

## 4. Библиотека (Читать/Слушать) — пробелы vs референс

Файл: `src/app/(app)/library/page.tsx`.

Сверка со скриншотами референса (`lexpring-rebuild-spec_3.md`, раздел 2) показывает, что реализовано **только** список текстов + FAB "+". Отсутствует:

### 4.1 Удаление текста
Сейчас нет НИ кнопки удаления, ни server action `deleteText`. Пользователь не может убрать текст из "Моих текстов", кроме как напрямую в БД.

```ts
// src/app/(app)/library/actions.ts — добавить
export async function deleteText(textId: string) {
  const supabase = await createClient();
  const { error } = await supabase.from("texts").delete().eq("id", textId);
  if (error) throw new Error(error.message);
  revalidatePath("/library");
}
```
+ маленькая кнопка ✕ на карточке (только для `own`-текстов, не для системных), с обычным паттерном `useTransition` как в `card-row.tsx` (Мозг) — скопировать оттуда подход.

### 4.2 Прогресс чтения (% read) и дата последнего чтения
В скриншотах референса на каждой карточке текста — зелёный прогресс-бар "% read" и "Last read: DD.MM.YYYY". Сейчас `texts` не хранит вообще никакого состояния прочтения на уровне текста (только глобальные `reading_sessions`, не привязанные к конкретному прогрессу внутри текста).

**Модель**: добавить таблицу (или поля прямо в отдельную join-таблицу, т.к. это per-user-per-text состояние, а `texts` может быть системным/общим для всех):
```sql
create table text_progress (
  owner_id uuid not null references profiles(id) on delete cascade,
  text_id uuid not null references texts(id) on delete cascade,
  last_page_index int not null default 0,
  percent_read int not null default 0 check (percent_read between 0 and 100),
  last_read_at timestamptz,
  primary key (owner_id, text_id)
);
-- RLS: owner_id = auth.uid(), аналогично остальным таблицам
```
- В читалке (`reader.tsx`) при смене страницы (`pageIndex`) и при "Завершить" — апсертить `text_progress` (`percent_read = round((pageIndex+1)/pages.length*100)`, `last_read_at = now()`).
- В библиотеке — джойнить `text_progress` для текущего пользователя, показывать прогресс-бар и дату.
- При открытии текста, если `last_page_index > 0`, открывать читалку сразу на этой странице (докрутить `useState(pageIndex, initialPageIndex)` в `reader.tsx` вместо жёсткого `0`).

### 4.3 Оценка времени чтения
Спека (исходный `lexpring-clone-spec.md`, раздел 4.2) требует "оценочное время чтения" на карточке. Простая формула: `Math.ceil(word_count / 200)` минут (200 слов/мин — стандартная средняя скорость чтения для этого жанра приложений). Добавить в `Section`/карточку текста: `≈{Math.ceil(word_count/200)} мин`.

### 4.4 "% новых слов в тексте" — персонализированная сложность
Спека называет это "сильным дифференциатором": показывать, сколько % слов в тексте пользователь ещё не видел (т.е. насколько текст "по силам"). Требует на каждую карточку библиотеки посчитать: уникальные слова текста (уже есть логика в `read/[textId]/page.tsx` — вынести в переиспользуемую функцию `computeUniqueWords(body)` в `src/lib/tokenize.ts`) минус пересечение с `vocabulary_items` пользователя (level>=1, т.е. хоть раз виденные). Дорого считать на каждую карточку списка при большом количестве текстов — можно закешировать в `texts.unique_word_count` (посчитать один раз при импорте текста) и считать "новизну" через join с `vocabulary_items` в момент рендера списка (один запрос на всю страницу, не N+1).

### 4.5 Коллекции (Collections)
В референсе — секция "MY COLLECTIONS" с пустым состоянием "No collections yet." и кнопкой "+New". Это пользовательские папки для группировки текстов. Не реализовано вообще (ни таблицы, ни UI).

```sql
create table collections (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references profiles(id) on delete cascade,
  name text not null,
  created_at timestamptz not null default now()
);
create table collection_texts (
  collection_id uuid not null references collections(id) on delete cascade,
  text_id uuid not null references texts(id) on delete cascade,
  primary key (collection_id, text_id)
);
```
UI: список коллекций на `/library` (аналогично списку колод в Мозге — переиспользовать паттерн `DeckCard`/`NewDeckModal`), внутри коллекции — фильтрованный список текстов, добавление текста в коллекцию — через меню на карточке текста ("Добавить в коллекцию" → модалка выбора).

### 4.6 Курсы (Courses)

## 6. Мозг (колоды) — пробелы и несогласованности

### 6.1 Учебные шаги (learning steps) не влияют на расчёт
`src/lib/srs.ts` — комментарий сам об этом честно говорит:
> "Упрощение: полноценные Anki-style learning/relearning steps... не реализованы — learning_steps/relearning_steps хранятся и показываются в настройках, но на расчёт интервалов пока не влияют."

Это значит: пользователь меняет "Learning steps (minutes): 1, 10" в Study Settings, ожидает, что новая карточка вернётся через 1 минуту, затем через 10 минут В ТОТ ЖЕ ДЕНЬ — а на деле карточка сразу уходит на `graduating_interval_days` (по умолчанию 1 день). Поле в UI **врёт**.

**Варианты**:
- (A, дешевле) Убрать поля Learning/Relearning steps из UI Study Settings, оставить только то, что реально работает (Daily Limits, Study Direction, SRS Algorithm, Display). Честно, но менее "по спеке референса".
- (B, дороже, но по-настоящему) Реализовать внутридневную очередь обучения: у карточки появляется временное состояние "learning" с `due_at` на уровне МИНУТ (не дней), отдельная очередь в UI ревью-сессии, которая подмешивает такие карточки чаще. Это фактически мини-переписывание движка SM-2 в сторону настоящего Anki. Дать этому отдельную задачу, не смешивать с остальным.

**Рекомендация**: сделать (A) сейчас (10 минут работы, убирает враньё), запланировать (B) как отдельную большую задачу если приложению нужна точная Anki-совместимость.

### 6.2 Нет ограничения new_cards_per_day отдельно от max_reviews_per_day
`src/app/(app)/brain/[deckId]/review/page.tsx`:
```ts
.limit(Math.max(settings.max_reviews_per_day, 20));
```
Тут ВСЯ очередь (и новые карточки с `repetitions=0`, и карточки на повторение) режется одним общим лимитом `max_reviews_per_day`. `new_cards_per_day` из настроек нигде не используется как отдельный кап. В Anki это два независимых лимита (иначе можно случайно "утонуть" в 200 новых карточках за один присест и никогда не дойти до настоящих повторений).

**Что делать**: разделить запрос на два — карточки с `repetitions=0` (новые, ограничить `new_cards_per_day`) и карточки с `repetitions>0` (на повторение, ограничить `max_reviews_per_day`), склеить и перемешать (или сначала повторения, потом новые — как настроишь).

### 6.3 Нет ограничения бесплатного тарифа на колоды/карточки
Сверка с `src/lib/subscription.ts` — там только `FREE_TEXT_LIMIT` и `FREE_DAILY_WORD_LIMIT`, ничего про деки/флэшкарты. `brain/actions.ts` (`createDeck`, `importFlashcards`) и `brain/[deckId]/actions.ts` (`addFlashcard`) не делают вообще никаких проверок плана.

**Решение — вопрос продуктовой логики, не только кода**: нужно явно решить, разрешено ли на бесплатном тарифе создавать неограниченное число колод/карточек. Если НЕТ (по аналогии с текстами/словами) — добавить `FREE_DECK_LIMIT`/`FREE_FLASHCARD_LIMIT` в `subscription.ts` и такие же проверки, что уже есть в `library/actions.ts`/`read/actions.ts`. Если ДА (например, "Мозг — это как раз то, что бесплатно, а платим за AI-фичи и импорт медиа") — оставить как есть, но явно задокументировать это решение в коде комментарием, чтобы не выглядело забытым багом при следующем ревью.

### 6.4 Нет редактирования карточки
`brain/[deckId]/page.tsx` — можно добавить и удалить карточку, редактирования нет. Добавить инлайн-редактирование front/back (аналогично паттерну в `import-modal.tsx`, где превью-карточки уже редактируемые инпуты — просто перенести тот же UI на постоянные карточки в колоде).

### 6.5 CSV-парсинг в импорте наивный
`src/app/(app)/brain/import-modal.tsx`, `parseFile`:
```ts
const rows = lines.map((l) => l.split(","));
```
Не обрабатывает запятые внутри значений в кавычках (стандартный CSV может содержать `"привет, как дела","hello, how are you"`). Если перевод сам содержит запятую (частый случай для фраз/идиом) — импорт сломает колонки.

**Что делать**: использовать минимальный CSV-парсер с поддержкой кавычек (можно написать вручную ~15 строк регуляркой, не обязательно тянуть библиотеку) или взять лёгкую зависимость (`papaparse` — популярный, бесплатный, MIT-лицензия).

### 6.6 Режимы "Выбор"/"Напечатать"/"Пары" не перепроверены после миграции на флэшкарты
Я протестировал только классический режим "Карточки" после переезда `srs_state`/`review_log` с `vocabulary_items` на `flashcards` (раздел 27 предыдущей сессии). `MultipleChoiceMode`, `TypeWordMode`, `MatchPairsMode` были переименованы (`headword→front`, `translation→back`) синтаксически корректно (проходят `tsc`/`eslint`), но **не проверены вручную в браузере** после рефакторинга. Стоит пройти их руками (или новой сессией) прежде чем считать полностью готовыми.

## 7. Читалка — дополнительные пробелы

### 7.1 TTS не показывает "сейчас читается" слово
Кнопка 🎤 читает всю страницу через `speechSynthesis`, но нет никакой визуальной синхронизации (подсветки текущего слова) во время чтения — просто голос идёт фоном. Веб-стандарт `SpeechSynthesisUtterance` поддерживает событие `boundary` (даёт индекс символа в момент произнесения каждого слова) — можно использовать для подсветки слова по мере чтения. Не критично, но заметно улучшает "read-along" ощущение, раз пользователю нравится эта механика (см. раздел 3 про YouTube — то же самое, но для текста).

### 7.2 Метрика времени чтения примитивна
`handleFinish` в `reader.tsx` считает `Date.now() - startedAt.current` — если пользователь свернул вкладку/телефон заблокировался на 20 минут, это всё равно засчитается как 20 минут активного чтения. Для более честной метрики можно слушать `document.visibilitychange` и вычитать время в фоне, либо просто не считать это критичным для MVP-уровня продукта (рекомендация: не чинить сейчас, слишком мелко относительно остального списка).

### 7.3 Ошибка перевода — ручной ввод не работает для одной и той же фразы дважды
В `handleManualTranslation` — если пользователь вводит перевод вручную для ФРАЗЫ, он просто кладётся в `popup.wordTranslation` локально (не персистится нигде, пока не нажата "+ В карточки"). Если попап закрыть и открыть слово/фразу заново — ручной перевод потеряется, придётся вводить заново. Не баг per se (соответствует текущей архитектуре "перевод не кешируется для фраз"), но стоит хотя бы закинуть ручной перевод во `translations_cache` при вводе (та же таблица, что уже используется для API-переводов) — тогда при повторном тапе на ту же фразу/слово `cachedTranslate` в `/api/translate/route.ts` найдёт его и не будет пытаться снова дёргать MyMemory (которая всё равно упадёт с той же ошибкой).

## 8. Многоязычность — открытый архитектурный вопрос

Сейчас `profiles.target_language`/`native_language` — по одному значению на пользователя. Всё завязано на эту пару (библиотека фильтрует по ней, Тетрадь получает слова без языкового разделения вообще — кстати, отдельно отметить: **`vocabulary_items` не хранит `language` вообще!** Если пользователь переключит `target_language` в Настройках (раздел 2 выше), старые слова в Тетради останутся видны вперемешку с новыми словами другого языка, потому что фильтрации по языку в Тетради просто нет — только в Библиотеке).

**Если планируется поддержка нескольких изучаемых языков одновременно** (что логично для языкового приложения в долгосрочной перспективе — многие пользователи учат 2+ языка) — нужно:
1. Добавить `vocabulary_items.language` (denormalized, копия `texts.language` в момент создания записи, либо через join, если слово без текста-источника — тогда брать текущий `target_language` профиля на момент создания).
2. Фильтровать Тетрадь по языку (селектор языка на экране Тетрадь, аналогично пилюле-селектору в референсе на Библиотеке/Мозге, которая сейчас статично показывает `{profile.target_language}` без возможности переключения).
3. Мозг/деки — тоже привязать к языку (`decks.language`?) или сделать язык-независимыми (декi могут быть смешанными по языкам — тоже валидный дизайн, но нужно решить явно).

**Рекомендация**: если это не горит прямо сейчас — оставить как есть (один активный язык), но зафиксировать это ограничение явно в UI (например, подсказка в Настройках "Смена языка скроет тексты и слова для предыдущего языка (они не удаляются)"), чтобы не путать пользователя.
