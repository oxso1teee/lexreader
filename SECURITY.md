# Security Policy

## Поддерживаемые версии

Один живой деплой — [lexreader.vercel.app](https://lexreader.vercel.app), всегда собран из `main`. Отдельных LTS-веток нет; фиксы безопасности идут прямо в `main`.

## Как сообщить об уязвимости

Предпочтительный способ — **[приватный GitHub Security Advisory](https://github.com/oxso1teee/lexreader/security/advisories/new)**: репорт не виден публично, пока мы вместе не решим, что фикс готов к раскрытию.

Если GitHub Advisories недоступны — email: [puchkov889@gmail.com](mailto:puchkov889@gmail.com) (тот же адрес, что и в [Политике конфиденциальности](https://lexreader.vercel.app/privacy)/[Условиях использования](https://lexreader.vercel.app/terms); выделенный security-адрес пока не заведён).

**Пожалуйста, не открывай публичный GitHub Issue для уязвимости** до тех пор, пока фикс не выкачен.

Просьба указать в репорте:
- Что затронуто (эндпоинт, страница, RLS-политика и т.п.) и версию/коммит, на которой воспроизвели.
- Шаги воспроизведения или PoC.
- Потенциальное воздействие, как его видите вы (утечка чужих данных, обход авторизации, RCE и т.п.).

Это соло/маленький проект — гарантированного SLA на ответ нет, но серьёзные находки (обход RLS, утечка чужих учётных данных, RCE) разбираются в приоритете.

## Что в зоне ответственности

- Само Next.js-приложение (`src/`) — авторизация, RLS-политики, серверные экшены, API-роуты.
- Миграции БД (`supabase/migrations/`) — схема, политики RLS, RPC с `SECURITY DEFINER`.
- `worker/youtube-ingestion` — отдельный сервис импорта YouTube.

## Что не в зоне ответственности этого репозитория

- Инфраструктура самих подрядчиков (Supabase, Vercel, Stripe, PostHog) — репортить им напрямую.
- Известные, уже принятые как build-tool-only риски: `npm audit` показывает уязвимости в транзитивных зависимостях `@capacitor/assets` (`tar`/`sharp`/`uuid` через `xcode`) — это dev-инструмент сборки мобильных иконок/сплэшей, не код, попадающий в рантайм приложения. Уже задокументировано в [`docs/release-2026-08-22/11_CHEKLIST_ZAPUSKA_V_STORY.md`](./docs/release-2026-08-22/11_CHEKLIST_ZAPUSKA_V_STORY.md) — повторно репортить не нужно, но если у тебя есть реальный сценарий эксплуатации именно через них — пиши, это меняет картину.
