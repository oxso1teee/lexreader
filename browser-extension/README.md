# LexReader — YouTube Bridge + тап-перевод

Расширение теперь совмещает две независимые функции:

1. **YouTube Bridge** — обходит блокировку `captionTracks` для облачных IP.
2. **Тап-перевод на любой странице** (docs/release-2026-08-22/10_VAU_NOVYE_FICHI_I_DIZAYN.md
   раздел C, Тир 3) — двойной клик по слову на изучаемом языке на **любом**
   сайте даёт тот же перевод-в-контексте и сохранение в словарь, что и в
   LexReader Reader. См. раздел «Тап-перевод» ниже.

YouTube часто скрывает `captionTracks` от IP облачных серверов, включая Vercel.
Расширение открывает нативную расшифровку в обычном Chrome пользователя,
собирает timestamp-строки из виртуализированной панели и передаёт готовые
сегменты в авторизованный LexReader.

Стороннее расширение **YouTube To Text** нельзя вызвать из LexReader: в его
`manifest.json` поле `externally_connectable` разрешает связь только с
`https://yt-to-text.com/*`. У LexReader нет доступа к его внутренним данным.
Поэтому мост реализован отдельно и не зависит от обновлений чужого расширения.

## Установка для разработки

1. Открыть `chrome://extensions`.
2. Включить **Режим разработчика**.
3. Нажать **Загрузить распакованное расширение**.
4. Скачать `lexreader-youtube-bridge.zip` из формы импорта LexReader и
   распаковать его либо выбрать папку `browser-extension` из репозитория.
5. Выбрать распакованную папку расширения.
6. Обновить страницу `https://lexreader.vercel.app/library/new`.
7. На вкладке YouTube должна появиться зелёная строка
   `LexReader Bridge подключён`.

После публикации расширения в Chrome Web Store ручная установка папки будет не
нужна.

## Что поддерживается

- обычные ссылки, `youtu.be`, Shorts и embed;
- ручные и автоматически созданные YouTube-субтитры;
- выбор дорожки языка, который пользователь изучает;
- таймкоды для синхронизации с YouTube Player;
- работа только на разрешённых доменах LexReader.

Основной источник — DOM нативной панели YouTube. Сборщик прокручивает панель,
дедуплицирует строки и проверяет, что длинная расшифровка доходит достаточно
близко к длительности видео. Перехват собственного `timedtext`-ответа YouTube
используется только как резервный путь после настоящей неудачи DOM-сбора.

Для отладки доступен `domOnly` в сообщении моста. При нём MAIN-world скрипт
вообще не устанавливает перехватчики `fetch`/XHR, а background не запускает
сетевой резервный путь.

Видео без caption track пока требуют отдельного speech-to-text провайдера.

## Тап-перевод на любой странице

Полностью отдельная от YouTube Bridge функция — общий только `background.mjs`
(один service worker на расширение) и сама идея "перевод + сохранение через
LexReader". Требует персональный API-токен вместо cookie-сессии — контент-
скрипт работает на произвольном стороннем сайте, где вкладки LexReader может
не быть вообще (см. `src/lib/extension-tokens.ts` и
`src/app/api/extension/translate-and-save/route.ts` в основном репозитории).

### Как включить

1. Открыть **LexReader → Настройки → Браузерное расширение** и создать токен
   (`···1234`, показывается один раз).
2. Открыть popup расширения (иконка в панели инструментов), вставить токен,
   выбрать языковую пару (изучаю/родной).
3. Нажать **«Включить на этой странице»** — работает до следующей перезагрузки
   страницы; повторное нажатие на уже активной странице выключает.
4. Дважды кликнуть по слову — всплывающая карточка с переводом; слово сразу
   сохраняется в словарь с тем же контекстным предложением.

### Как это устроено (минимальные permissions)

Никакого `<all_urls>` и никакого статического `content_scripts.matches` на
произвольные сайты. Вместо этого:

- **`activeTab` + `scripting`** — код (`word-tap-core.js` + `word-tap.js`)
  инжектируется через `chrome.scripting.executeScript` только по явному
  клику пользователя в popup, только во вкладку, которая уже активна в этот
  момент. Расширение не имеет постоянного доступа ни к одному сайту, пока
  пользователь сам не попросит.
- **`storage`** — токен и языковая пара хранятся в `chrome.storage.local`
  (только на устройстве пользователя).
- **`host_permissions`** для доменов LexReader (тот же список, что уже
  использует YouTube Bridge, `allowed-origins.test.mjs` держит их в
  синхроне) — нужны, чтобы `background.mjs` мог сделать сетевой запрос к
  `/api/extension/translate-and-save`. Запрос идёт из background, а не из
  контент-скрипта на стороннем сайте: у контент-скрипта нет доступа в обход
  `connect-src` CSP той страницы, куда он инжектирован, у background —
  есть.

### Детектор языка

`document.documentElement.lang` (ближайшее объявление языка самой страницей)
сравнивается с выбранным "изучаю" — при явном несовпадении показывается
ненавязчивое предупреждение, тап всё равно работает (многие страницы вообще
не объявляют `lang`, блокировать тап в этом случае значило бы просто не
работать на большинстве реальных сайтов). Логика — `word-tap-core.js`
(`normalizePageLang`/`langMismatchWarning`), тестируется без DOM в
`word-tap-core.test.mjs`.

### Охват MVP

Только отдельные слова (двойной клик = выделение слова браузером), не фразы —
то же ограничение, что и на бэкенде (`api/extension/translate-and-save`
отклоняет запрос с пробелом в `word`).
