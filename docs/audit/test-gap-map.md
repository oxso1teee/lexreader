## Карта покрытия по фичам

| Фича | Тип теста | Файл | Что проверяется | Критичный пробел |
|---|---|---|---|---|
| Импорт карточек (CSV/TSV/JSON) | Unit | `import-cards.test.ts` | Парсинг, дедупликация, отклонение мусора | Нет теста на реальный UI-путь `import-modal.tsx` |
| Browser extension | Unit | `youtube-transcript.test.mjs` | Video ID, парсинг субтитров | Нет теста на message-passing слой (`background.mjs`↔`lexreader-bridge.js`) |
| Login/auth | E2E | `auth.spec.ts` | Верный/неверный пароль, несуществующий email (анти-энумерация), запрос сброса пароля, **полный** цикл сброса через реальное письмо (Inbucket) | Нет теста logout, нет теста rate-limit срабатывания (не проверяет, что N+1-я попытка реально блокируется) |
| Регистрация/онбординг | E2E | `onboarding-first-win.spec.ts` | Полный цикл: регистрация → профиль → первый цикл текст/слово/карточка | — |
| Мозг/Тетрадь | E2E | `brain-notebook.spec.ts` | Создание колоды, ручное добавление карточки, ручное добавление слова | **Нет теста самой сессии повторения** (grade-кнопки, FSRS/SM-2 расчёт, смена due-даты) |
| Чтение | E2E | `reading.spec.ts` | Открыть текст, тап по слову, перевод, смена уровня, завершение | Нет теста на выделение фразы (long-press), нет теста Watch Mode |
| Оплата | E2E | `payment.spec.ts` | Pricing показывает планы, dev fallback работает без ключей Stripe | Реальный Stripe checkout тест **пропущен** (нет `STRIPE_SECRET_KEY` в тестовом окружении) — это ожидаемо, не баг |

## Критичные пробелы (по явному списку из задания)

| Область | Есть тест? | Комментарий |
|---|---|---|
| Импорт карточек | частично | только парсер, не UI/paywall-путь |
| Browser extension | частично | только чистая логика, не IPC |
| E2E в целом | ДА | 5 файлов, стабильно проходят (см. `production-parity.md`) |
| Auth | ДА (сильное покрытие) | включая полный цикл сброса пароля через настоящее письмо |
| RLS | **НЕТ** | Нет автоматического теста, что RLS реально блокирует чужие данные (только код-ревью через миграции, см. `database-rls-map.md`) — раньше в истории проекта это проверялось вручную ("Verify DB trigger backstop blocks direct REST bypass"), но не закреплено как регрессионный тест |
| Stripe | частично | webhook-обработчик не имеет собственного теста (сигнатура, идемпотентность, ошибка БД) — E2E покрывает только UI-часть без ключей |
| Reader | ДА | основной путь |
| PDF | **НЕТ** | ни unit, ни e2e |
| YouTube (импорт) | **НЕТ e2e** | есть unit на чистую логику транскрипта, нет теста полного пути сохранения источника |
| Review (повторение карточек) | **НЕТ** | ни unit на `reviewSrsState`, ни e2e на сессию — единственная проверка после сегодняшних правок делалась вручную в браузере в рамках прошлой сессии, не закреплена |
| PostHog | **НЕТ** | ни один тест не проверяет, что события реально отправляются/не содержат PII — только код-ревью в `ai-analytics-map.md` |
| Push | **НЕТ** | ни unit, ни e2e |
| Delete/Export аккаунта | **НЕТ** | ни unit, ни e2e на `deleteAccount`/`/api/export/*` |

## RECOMMENDATION

Первый кандидат на закрытие пробела с наибольшим отношением
риск/стоимость: unit-тест на `src/lib/srs.ts` (`reviewSrsState`) —
чистая функция без побочных эффектов, дёшево тестируется, и именно
этот файл будет заменяться при будущей миграции на `ts-fsrs`
(`docs/fluency-os/02-phrase-model-fsrs.md`) — тест до миграции даст
эталон поведения для сравнения "было/стало".
