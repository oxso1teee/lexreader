## Прогон 3 → 1 падение: причина установлена (тест, не приложение и не инфраструктура)

`practice-modes-feedback.spec.ts:126` «Match mode: mismatched pairs differ by more than color» — live-region остался
пустым после клика пары (`Expected "Неверно", Received ""`). Артефакты упавшего прогона (trace) к моменту разбора были
стёрты следующими запусками Playwright, поэтому причину искал воспроизведением на живом приложении.

**Причина: гонка теста с гидратацией.** `match-pairs-mode.tsx` рендерится на сервере; кнопки приходят в HTML видимыми
(для Playwright они уже «кликабельны») раньше, чем React навесил обработчики. Клик в это окно молча теряется. Тест после
`toBeVisible()` сразу кликал слово и перевод: если оба клика (или первый) попали до гидратации, выбор не регистрируется,
пары не разрешаются, `announcement` остаётся `""` — ровно симптом из лога. Ослабленные assertions ни при чём: проверка
«Неверно» корректна.

Что проверено диагностическим скриптом на изолированном приложении:

| Гипотеза | Результат |
|---|---|
| SSR-порядок кнопок ≠ порядок после гидратации (из-за `Math.random` в `useState`) | **Нет**: совпал 6/6, ошибок гидратации в консоли нет |
| Клик до гидратации теряется | **Да**: `hydratedAtClick=false`, live-region `""` |
| Тёплый кэш, CPU ×1, как в обычном тесте | 8/8 кликов дошли (отсюда редкая падаемость: 1 раз за ~10 запусков) |
| Холодная загрузка, CPU ×1, **без** ожидания гидратации | «Неверно» озвучено 2/6 |
| Холодная загрузка, CPU ×8, **без** ожидания | 0/6 |
| Холодная загрузка, CPU ×1 и ×8, **с** ожиданием гидратации | 6/6 и 6/6 |

**Классификация:** проблема теста (нет ожидания готовности), усиливаемая нагрузкой; не ошибка логики приложения. Побочно:
в приложении серверно-отрисованные кнопки не реагируют до гидратации — свойство SSR, общее для проекта, в этой задаче не менялось.

**Исправление** (без пауз и без ослабления assertions): `waitForHydration(locator)` в `e2e/helpers.ts` — `expect.poll` по наличию
`__reactProps$…` на DOM-узле; вызывается в Match-тесте после `toBeVisible()`. Повтор: файл целиком — 3/3 зелёные, Match ×10 —
10/10 зелёные (`match-mode-fixed.log`, `match-mode-fixed-repeat10.log`), при этом хост был нагружен сильнее, чем в упавшем
прогоне (load average ≈13, тест шёл 14–37 с вместо 5 с).

Остаточный риск: тем же способом могут флакать другие e2e, которые кликают/вводят сразу после видимости SSR-элемента
(`Choice`/`Type` в том же файле и др.). Падений в прогонах не было, поэтому они не менялись; при появлении — применять
`waitForHydration`.
