# 05 — Юридические требования сторов и материалы карточки приложения

Опирается на инвентарь данных из файла 03, раздел 1. Каждый магазин
требует формально заполненную декларацию о данных — это не формальность,
а обязательное поле в форме публикации, без него релиз не пройдёт.

## 1. Google Play — форма Data Safety

Обязательная секция в Play Console. Нужно явно указать по каждому типу
данных: собирается ли, передаётся ли третьим лицам, для чего, шифруется
ли при передаче, можно ли попросить удаление.

Черновой список для LexReader (перепроверь перед заполнением по факту
кода, файл 03 раздел 1 — отправная точка):

- **Личная информация**: email — собирается (регистрация), не передаётся
  третьим лицам напрямую (кроме Stripe для платящих — это уже "передача
  третьей стороне для целей платежа", это отдельная галочка в форме).
- **Финансовая информация**: данные подписки/платежа — обрабатывает
  Stripe, у тебя хранится только статус и `stripe_customer_id`.
- **Фото**: собираются при OCR-импорте — уточни, хранятся ли постоянно
  в Storage или временные.
- **Данные о действиях в приложении**: PostHog — тип "Analytics", с
  указанием, что это для собственных нужд разработчика (product
  analytics), не для рекламы.
- **Право на удаление данных** — у тебя уже есть `deleteAccount`, это
  прямо отвечает на обязательный вопрос формы "может ли пользователь
  запросить удаление данных".

## 2. Apple — Privacy Nutrition Label + App Privacy Details

Похожая по смыслу форма в App Store Connect, но с более строгой
категоризацией ("Data Used to Track You" отдельно от "Data Linked to
You" отдельно от "Data Not Linked to You"). PostHog аналитика, если
она не анонимизирована по `owner_id`/persistent ID — скорее всего
попадает в "Data Linked to You", не "Not Linked". Заполняется отдельно
от Google, но исходный список данных (файл 03, раздел 1) — тот же.

## 3. Возрастной рейтинг

LexReader — образовательное приложение без контента для взрослых,
скорее всего 4+ (Apple) / "Everyone" (Google) — но обе формы задают
опросник (насилие, контент 18+, азартные игры, генерируемый пользователем
контент и т.д.). Отдельно учти: пользователь может импортировать
**произвольный внешний контент** (статьи по URL, YouTube-видео) — это
теоретически может содержать что угодно, включая контент 18+, если
пользователь сам это выберет для изучения языка. Стоит явно продумать
формулировку в анкете рейтинга (обычно это не блокирует низкий рейтинг,
если ты явно не таргетируешь такой контент и у тебя есть Условия
использования, запрещающие импорт незаконного контента — уже похоже
есть в общих чертах, проверить/усилить).

## 4. Обязательные страницы и тексты

- **Terms of Service / Условия использования** — есть
  (`src/app/terms/page.tsx`), но нужно актуализировать раздел про
  оплату под фактическое поведение (сейчас там, по июльскому аудиту,
  было расхождение между текстом про "настоящую периодическую оплату"
  и реальным поведением тестового режима — перепроверь текущую версию
  страницы на соответствие фактическому состоянию Stripe в проде, файл
  02 пункт A.3 связан с этим же).
- **Privacy Policy / Политика конфиденциальности** — есть, нужно
  дополнить: рабочий email (файл 02, A.3), место хранения данных и
  трансграничную передачу (файл 03, раздел 2 — 152-ФЗ), список
  подпроцессоров (Supabase, Stripe, PostHog, MyMemory API — каждый,
  кому уходят пользовательские данные, должен быть перечислен).
- **Account Deletion (Apple, обязательное требование с 2022 года)** —
  у тебя уже реализовано и доступно из настроек внутри приложения
  (`delete-account-actions.ts`) — это правильно закрывает требование
  Apple "any app that supports account creation must also support
  account deletion within the app". Убедись, что путь к этой функции
  очевиден и не спрятан глубже 2-3 тапов от главного экрана настроек.

## 5. Материалы карточки в сторе (ASO — App Store Optimization)

Понадобится на каждый стор отдельно (Google Play, App Store, RuStore —
у каждого свой набор требований к размерам):

- Иконка приложения (высокого разрешения, 1024×1024 для App Store,
  512×512 для Google Play) — нужно сделать финальную версию, не
  переиспользовать web-favicon впрямую без проверки на читаемость в
  маленьком размере.
- Скриншоты (минимум 2-3, обычно требуется под несколько размеров
  экрана — телефон и планшет отдельно у Apple). Сделать на реальных
  экранах: онбординг, читалка с переводом слова, сессия повторения
  карточек, экран прогресса — самые "продающие" экраны.
- Короткое и длинное описание — короткое (до ~80 символов у Google) и
  полное (до 4000 символов) — на русском в первую очередь, если
  аудитория русскоязычная; английская версия отдельно, если целишься
  за пределы РФ.
- Ключевые слова (Apple — отдельное поле 100 символов, Google — влияют
  через текст описания) — под тематику "изучение языка", "английский
  по текстам", "флеш-карточки", "SRS", конкурентный анализ по
  существующим приложениям в той же категории стоит сделать отдельно,
  не входит в этот технический план.
- Промо-видео (опционально, но сильно повышает конверсию установки) —
  не блокер для первого релиза.

- [ ] Privacy Policy содержит: список данных, подпроцессоров, место
      хранения, срок хранения, право на удаление, контакт
- [ ] Data Safety (Google) / Privacy Nutrition Label (Apple) заполнены
      и соответствуют Privacy Policy дословно (несовпадение — частая
      причина отклонения на ревью)
- [ ] Возрастной рейтинг пройден в обеих формах
- [ ] Удаление аккаунта доступно и заметно внутри приложения
- [ ] Иконки всех нужных размеров готовы
- [ ] Скриншоты сделаны на актуальной сборке (не на старом дизайне)
- [ ] Описание на русском (и английском, если нужно) готово
- [ ] Аккаунты разработчика (Apple $99/год, Google $25 разово, RuStore
      — по юрлицу/ИП) заведены и оплачены заранее
