# 10 — ВАУ: новый контент, фичи и визуальный редизайн

Этот файл — не про "почини баг", а про "сделай так, чтобы человек не хотел
выходить". Составлен по трём источникам: собственный аудит проекта
`docs/ui/current-ui-audit.md` (02.08, реальное чтение кода, не мнение),
`docs/GROWTH_IDEAS_2026-07-24.md` (разбор конкурента Lexpring, уже
приоритизирован) и `docs/fluency-os/` (12-файловый план на голос/AI-твина,
частично уже реализован раньше графика). Плюс новые идеи, которых не было
ни в одном старом документе.

## A. Почему ощущение "сайт 2010" — не ощущение, а факт

Прямые цитаты из `docs/ui/current-ui-audit.md`:

- **Нет библиотеки анимаций вообще** — grep по `framer-motion`/`motion` даёт
  0 совпадений во всём проекте. Единственная анимация на всё приложение —
  один "переворот" карточки при показе ответа в повторении.
- **Иконки — вперемешку** — 5 самодельных SVG для навигации (нормально), но
  эмодзи (📷 🏠 и т.д.) для всего остального через строковые пропсы
  `icon: string`. Нет единой библиотеки иконок (`lucide-react` и подобные —
  не установлены).
- **Всего 3 именованных цветовых роли** (`background`/`foreground`/`card`) —
  нет `primary`/`success`/`warning`/`danger`/`focus-ring` как токенов,
  бордеры и вторичный текст собраны вручную через `opacity`-модификаторы в
  десятках файлов.
- **1440px и шире — пусто.** Контент верстается в колонку `max-w-2xl`
  (672px) на каждой странице, по бокам — голый фон. Нижняя навигация
  одинаковая что на 360px, что на 1440px — растянутый мобильный бар вместо
  desktop-интерфейса.
- Тёмная тема есть, но только системная — нет переключателя в интерфейсе.

Хорошая новость: Slice 1-2 редизайна (App Shell, Today, Progress) уже
задеплоены в прод, и по докам `docs/ui/m3-slice*` этот процесс шёл ещё
глубже (Library/Reader v2, Brain/Review, вокабуляр v2) — то, что видно
на сайте прямо сейчас, скорее всего заметно свежее, чем снимок в аудите от
02.08. Но фундаментальный диагноз (нет моушена, нет богатой палитры, нет
настоящего desktop-макета) остаётся верным на уровне инфраструктуры дизайна
— ни один из этих слайсов не устанавливал анимационную библиотеку и не
расширял токены.

## B. Визуальный слой — самое дешёвое "вау" на единицу усилия

Не редизайн с нуля (дорого, рискованно ломает всё разом) — точечные, но
заметные добавки поверх уже существующей структуры.

1. **Поставить библиотеку анимаций** (`framer-motion`/`motion` — 40KB,
   индустриальный стандарт для React) и добавить moments of delight
   в 3-4 самых частых точках контакта:
   - Завершение сессии повторения — конфетти/анимация успеха, не просто
     текст "Сессия завершена".
   - Достижение дневной цели/streak milestone — тот же принцип.
   - Правильный/неправильный ответ в review — сейчас просто цвет, добавить
     микро-анимацию (bounce/scale) без раздражающей задержки.
   - Переходы между страницами внутри `(app)` — сейчас, вероятно, жёсткая
     смена без transition (Next.js App Router поддерживает это нативно
     через `motion`/View Transitions API).
2. **Расширить design tokens** в `src/app/globals.css`/`src/styles/tokens.css`
   — добавить `primary`/`success`/`warning`/`danger`/`focus-ring` как
   именованные роли, унифицировать текущий ad hoc `opacity`-паттерн бордеров.
   Не менять существующие `caramel`/`forest` акценты слайсов — расширять,
   не переписывать.
3. **Единая иконочная система** — поставить `lucide-react`, заменить
   разрозненные эмодзи на согласованные SVG-иконки там, где это выглядит
   "недоделанным" (карточки функций, кнопки действий), оставить эмодзи
   осознанно только там, где они дают тёплый/человечный тон (пустые
   состояния, поздравления) — не убирать эмодзи целиком, это другая крайность.
4. **Настоящий desktop-макет** — если Slice 3+ ещё не закрыли этот пункт
   (проверить на живом проде на широком экране), это самое заметное
   "выглядит как сайт 2010" ощущение из всех: растянутая на весь экран
   узкая колонка с пустыми полями по бокам — типичный маркер недоделанного
   веб-продукта.
5. **Переключатель тёмной/светлой темы** в интерфейсе — сейчас только
   системный, добавление ручного переключателя (`next-themes` или ручная
   реализация через `data-theme`) — маленькая, но ожидаемая пользователем
   деталь в 2026 году.
6. **Лендинг/маркетинговая страница** — то, что видят App Store ревьюеры и
   новые пользователи первым делом. Стоит отдельно вложиться в визуальный
   hero-блок, а не только во внутренние экраны — первое впечатление весит
   больше, чем кажется.

## C. Контент и фичи — по тирам стоимости

### Тир 1 — бесплатно, быстро, эффект сразу (из `GROWTH_IDEAS`)

- Итоговый интервал на кнопках оценки повторения ("через 3 дня")
- Живой счётчик ответов во время сессии повторения
- Рейтинг "твои самые слабые слова" в статистике (данные уже есть)
- Интерактивные тултипы на графиках статистики
- Звёздочка "избранное слово" — независимо от статуса изучения
- Счётчик "58 записей" в шапке Тетради

### Тир 2 — контент, удерживающий новичка (высокая ценность, требует контентной подготовки)

- Готовые стартовые колоды A1-B2 по частотным спискам (NGSL) — новый
  пользователь получает мгновенную ценность в день установки, а не пустой
  Мозг
- Коллекции для многосерийных текстов (книга/сериал одним прогресс-баром)
- Голосовой ввод слова через Web Speech API (бесплатно, встроено в браузер)

### Тир 3 — настоящие крючки, без AI (бесплатно по деньгам, дорого по разработке)

- Визуальный Language Twin — не только цифры в статистике, а растущий
  "двойник", с возможностью поделиться прогрессом в соцсети (органический
  канал роста)
- Расширение браузерного расширения с YouTube на весь интернет — тап по
  слову на любой странице на изучаемом языке, не только импортированный
  контент
- Живые дуэли по словарю 1 на 1 (реалтайм quiz против друга/случайного
  пользователя с той же языковой парой)
- Соревновательность — недельная лига/лидерборд среди пользователей
- Виджет на главном экране телефона (слово дня/стрик) — актуален вместе с
  файлом 04, часть ценности нативной обёртки

### Тир 4 — требует AI-провайдера (реальные деньги за токены, инфраструктура)

Сейчас в приложении **ноль LLM-провайдеров** — только бесплатный
MyMemory-переводчик. Всё из этого тира — решение того же масштаба, что
файл 04 (мобильная стратегия): выбор провайдера (OpenAI/Anthropic/другой),
бюджет на токены, новый код интеграции.

- Персонализированные истории/диалоги из твоих слабых слов — ежедневный
  сгенерированный текст, вплетающий именно те слова, на которых спотыкаешься
- Адаптивный пересказ любого текста под твой текущий уровень (i+1)
- Голосовая AI-симуляция разговора (`docs/fluency-os/06-voice-simulation.md`
  — уже есть детальный план, не реализован)
- AI-профиль ошибок с отчётом "топ-3 ошибки этой недели"
  (`docs/fluency-os/07-error-memory-feedback.md` — тоже уже спланирован)

## D. Рекомендуемый порядок

1. **Визуальный слой (раздел B)** — не требует денежных решений, самый
   заметный эффект на "ощущение продукта" за один заход. Начать отсюда.
2. **Тир 1** — параллельно или сразу следующим шагом, тоже бесплатно и
   быстро.
3. **Тир 2** — стартовые колоды дают реальный buisness-эффект (удержание
   новых пользователей), но требуют контентной подготовки (словарные данные
   по языковым парам) — отдельная задача, не чисто код.
4. **Тир 3** — по одному, начиная с самого дешёвого (виджет, если уже
   решили про Capacitor из файла 04; визуальный Twin — если хочется
   вирусности).
5. **Тир 4** — только после осознанного решения платить за AI-провайдера.
   Не начинать случайно "по пути" — это отдельный бюджет и отдельная
   архитектура.

Файл 04 (сторы) и этот файл частично пересекаются в разделе про виджеты и
нативные push — если решишь двигаться по Capacitor, часть тира 3 становится
дешевле делать сразу в связке с нативной обёрткой, а не отдельно на вебе.
