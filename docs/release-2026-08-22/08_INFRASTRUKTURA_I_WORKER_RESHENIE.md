На `/home/sergey/Документы/projects/English_teacher_AI` есть код и
документы, которых нет в `github.com/oxso1teee/lexreader` на ветке
`main` (последний пуш — 13.08.2026, `4871efd`):

- `research/youtube-transcript/` — ~25 debug/research-скриптов и
  Python-окружение `whisper-venv` — рабочие материалы исследования, не
  часть приложения как таковая.
- `render.yaml` в корне проекта — конфиг деплоя на Render.com.
- Три документа в `docs/ui/`, датированные 20.08 (на неделю новее
  последнего пуша): `m3-slice12-production-architecture.md`,
  `m3-slice12-gate3-video-reader.md`, `m3-slice12-gate2c-browser-bridge-primary.md`
  — и, по всей видимости, связанный с ними код (Video Reader v2 для

  этот файловый мост — только чтение файлов).

Судя по содержанию этих документов, это не заброшенная ветка
экспериментов, а **реально протестированная, работающая доработка**:
переработанный видео-плеер для `/watch` с синхронизацией по субтитрам,
тапом по слову и выделением фразы, подтверждённая записями в базе
данных (`vocabulary_contexts` с `source_timestamp_ms`) и прогонами через

Отдельно там же зафиксировано важное и уже принятое архитектурное
решение: серверный воркер (`worker/youtube-ingestion/`) **осознанно

хостинга со стороны YouTube, Whisper упирается в лимит памяти 512 МБ),
и вместо серверной обработки основным способом извлечения субтитров
стало браузерное расширение (Gate #2C).

## 2. Что нужно решить (это твоё решение, не техническое)

1. **Это реально готово к пушу, или есть незавершённые куски?** Открой
   актуальный статус в своём редакторе/Claude Code локально (`git
   status`, `git log --oneline -20` — у меня нет инструмента выполнить
   это на твоей машине через этот мост, только читать файлы). Если
   тесты по видео-ридеру проходят и код рабочий — запушь его в `main`
   (или в отдельную ветку и PR, если хочешь код-ревью перед мержем) как
   можно скорее. До этого момента **любой анализ в файлах 01-07 этого
   плана, сделанный по коду на GitHub, не учитывает эту работу** —
   значит часть находок про `/watch` может быть уже неактуальна или,
   наоборот, актуальна по-другому в переработанном виде.
2. **Судьба `worker/youtube-ingestion/`** — раз он официально
   "припаркован" в самих же твоих документах, реши явно: удалить из
   рабочей копии (оставить только в истории git, не тащить мёртвый вес
   в каждый последующий анализ и в размер репозитория), или оставить
   как задел на будущее с явной пометкой в `README.md`, что сейчас не
   используется и почему. Молчаливое "и то, и то одновременно лежит в
   папке без объяснений" — то, что путает любой следующий анализ
   (в том числе мой сегодняшний).
3. **Судьба `research/youtube-transcript/`** — это explicitно
   исследовательские/debug-материалы, не продакшен-код. Рекомендация:
   вынести из основного репозитория проекта в отдельное место (или хотя
   бы в `.gitignore`, если там реально ничего ценного для будущих
   решений) — `whisper-venv/` внутри неё, судя по списку файлов, тянет
   за собой полноценное Python-окружение с зависимостями, это не должно
   жить рядом с Next.js-приложением ни функционально, ни по гигиене
   репозитория.
4. **`render.yaml` — что это, живой план или отвергнутая идея?** Если
   Render был опробован и не подошёл (см. пункт про то, почему воркер
   "припаркован") — а конфиг остался в корне — либо ты по факту
   переезжаешь на Render целиком (не только воркер, но и сам сайт), и
   тогда это часть будущего плана хостинга, либо это мусор от
   эксперимента, который стоит убрать, чтобы не запутывать себя же
   через полгода.

## 3. Почему это файл 08, а не файл 01

Формально по номеру он последний перед мастер-планом — но по порядку
выполнения (файл 00 уже об этом говорит) сделай его первым. Смысл в
том, что весь план 01-07 построен на снимке состояния GitHub `main` на
13.08 плюс сегодняшних живых проверках — это осознанная, зафиксированная
база для сравнения. Как только ты синхронизируешь локальную работу с
`main`, имеет смысл прогнать быструю повторную проверку (`npm run
typecheck && npm run lint && npm run build && npm run test:ui` — все
команды уже есть в `package.json`) на новом состоянии и свериться,
не изменилось ли что-то из находок файлов 01-07 применительно к новому
коду видео-ридера.
