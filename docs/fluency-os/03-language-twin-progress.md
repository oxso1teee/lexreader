# Фаза 3 — Language Twin v1 (честная версия, без придуманных цифр)

**Ворота:** нет — расширение уже существующей Статистики, без новых сервисов.
**Источник:** v1 §3.1 (Language Twin), v3 §98 «Progress page».

## Важное ограничение, которое обязательно соблюдать

v1 и v3 показывают пример профиля с цифрами вроде «Устная речь 62%»,
«Готовность к интервью 45%» — эти цифры **не выводятся ни из чего**,
что реально существует в проекте на этой фазе. Речи (Фаза 6) и
разбора ошибок (Фаза 7) ещё нет. Показывать выдуманные проценты —
прямой обман пользователя, и он это быстро заметит: реальный
разговор с воображаемой оценкой «45% готовности к интервью» ничего
не подтверждает.

**Правило Фазы 3: показывать только метрики, которые честно
считаются из существующих данных.** Разделы, для которых данных ещё
нет (устная речь, ошибки конструкций), либо не показывать вообще,
либо показывать как явно подписанное «Скоро — после первой
голосовой сессии», а не как готовое число.

## 3.1 Что уже есть и переиспользуется

`src/app/(app)/progress/page.tsx` уже считает: количество слов по
уровням знания (0–4), полосу активности (`activity-heatmap.tsx`),
самые сложные слова (`hardest-words.tsx`), достижения
(`achievements-shelf.tsx`), личные рекорды (`personal-records.tsx`).
Это уже частично Language Twin — просто не собрано в один понятный
«профиль».

## 3.2 Новый раздел — «Языковой профиль» на `/progress`

Новый компонент `src/app/(app)/progress/language-profile.tsx`,
рендерится первым на странице (`page.tsx`), три честные метрики:

1. **Словарный запас** — `% слов на уровне 3–4 (Знаю значение/Овладел)
   от всех сохранённых слов`. Источник: уже существующий запрос по
   `vocabulary_items`/`flashcards` с `level`/`fsrs_state` (после
   Фазы 2 — `fsrs_state = 2` (Review) как прокси «знаю»).
2. **Устойчивость повторения** (retention) — `% ревью с оценкой
   Good/Easy за последние 30 дней от всех ревью за период`. Источник:
   `review_log.grade`, `reviewed_at >= now() - interval '30 days'`.
   Это прямой, честный аналог «насколько ты действительно помнишь
   то, что учил» — почти то же самое, что v1 называет «сильные
   конструкции», только без придуманной категоризации по грамматике.
3. **Регулярность чтения** — переиспользовать данные, которые уже
   считает `activity-heatmap.tsx` (дней с активностью за 30 дней),
   показать как процент от 30.

Компонент — три `stat-card.tsx` (уже существующий паттерн) в ряд,
плюс блок «Скоро» ниже:

```tsx
<div className="rounded-2xl border border-dashed border-black/15 p-4 text-center dark:border-white/20">
  <p className="text-sm text-black/50 dark:text-white/50">
    Устная речь и разбор конструкций появятся здесь после первой
    голосовой тренировки.
  </p>
</div>
```

Не превращать это в фейковый прогресс-бар «0%» — прямой текст честнее.

## 3.3 Данные для будущего расширения — минимальная миграция

Единственное реальное дополнение схемы в этой фазе —
`supabase/migrations/0033_learner_profile_snapshot.sql`:

```sql
create table learner_profile_snapshots (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references profiles(id) on delete cascade,
  vocabulary_score numeric not null,
  retention_score numeric not null,
  consistency_score numeric not null,
  computed_at timestamptz not null default now()
);

alter table learner_profile_snapshots enable row level security;
create policy "learner_profile_snapshots: owner read" on learner_profile_snapshots
  for select using (owner_id = auth.uid());
grant select on learner_profile_snapshots to authenticated;
```

Заполняется раз в сутки лёгким cron-джобом (переиспользовать
существующий паттерн Vercel Cron из `vercel.json`, как уже сделано
для push-напоминаний) — считает три метрики из 3.2 и пишет строку.
Даёт историю профиля для будущего line-chart («как менялся словарный
запас за месяц») без пересчёта на лету каждый раз. Если это кажется
избыточным для этой фазы — можно отложить cron и просто считать
метрики на лету при каждом заходе на `/progress`; таблицу всё равно
завести, чтобы Фазы 6–7 могли начать писать в неё дополнительные
колонки (`speaking_score`, `error_reduction_score`), не создавая
новую сущность с нуля.

## Критерий готовности фазы

- `/progress` показывает «Языковой профиль» с тремя честными
  метриками и блоком «Скоро» без придуманных чисел.
- Миграция применена локально и в проде.
- Метрики совпадают с ручным пересчётом по сырым данным (проверить
  на своём тестовом аккаунте: сравнить % retention с вручную
  посчитанным по `review_log` за 30 дней).
- `npx tsc --noEmit`, `npx eslint` — чисто, задеплоено, проверено на проде.
