# Фаза 11 — Тарифы и публичный запуск

**Ворота:** Фазы 9–10 закрыты (или сознательно пропущены, если
команда так и остаётся из одного человека — в этом случае «запуск»
означает не пресс-релиз, а спокойное открытие регистрации всем
желающим после Bootcamp).
**Источник:** v1 §15, §26; v2 §73 (release gate); v3 §109
(«Pricing page UX»), §140–150 (release checklist/content).

## 11.1 Тарифы — на что ориентироваться

Из всех трёх документов цифры не менялись: Free (чтение, ограниченный
импорт, 1 диагностическая voice-сессия) / Personal €9–15/мес / Speaking
Pro €20–30/мес / Career Pack €29–79 разово / Teams — по запросу.
**Не выводить на страницу цен больше 3–4 вариантов одновременно**
(правило v3 §109, уже зафиксировано в `docs/COPYWRITING.md`, Фаза 1)
— Teams, если понадобится, продаётся отдельно, не через self-serve
pricing page.

Реальные цифры (€9 или €15? 120 голосовых минут или 60?) — калибровать
по ответам из Bootcamp (Фаза 4, поле «сколько готов платить») и по
фактической себестоимости STT/LLM/TTS на голосовую минуту (посчитать
после первых 20+ реальных голосовых сессий Фазы 6 — не раньше, цифры
без данных будут гаданием).

## 11.2 Контекстный пейволл (уже смакетирован — Экран 10)

Правило v3 §110: никогда не блокировать вход в приложение целиком.
Пейволл — контекстный, в моменте, когда лимит реально исчерпан
(«Ты использовал 5 бесплатных голосовых минут. На Pro — 120 в
месяц»), не полноэкранная стена сразу при входе.

## 11.3 Release-контент чеклист

Из v3 §140, к моменту публичного открытия должно быть готово:
лендинг (обновлён по позиционированию Фазы 1), демо-режим (без
регистрации — если решено делать, см. v3 §112), скриншоты, короткое
видео (60 сек), FAQ, страница цен, help center (минимум — несколько
статей по самым частым вопросам из поддержки Bootcamp), changelog,
публичный status (можно начать с простой страницы вида «всё работает»
без отдельного сервиса), privacy policy и terms (уже есть в проекте),
политика возврата, канал поддержки.

## 11.4 Финальный release gate — единый чеклист

Объединение 14-пунктного продуктового чеклиста v3 §150 и
инфраструктурного чеклиста v2 §73 в один — источник истины при
принятии решения «открываем регистрацию всем»:

- [ ] Лендинг объясняет продукт за 10 секунд.
- [ ] Онбординг проходится без посторонней помощи.
- [ ] Today даёт один понятный следующий шаг.
- [ ] Первая ценность достигается меньше чем за 10 минут от регистрации.
- [ ] Миссия имеет конкретный измеримый результат.
- [ ] Голосовая сессия стабильна (проверено минимум 20 раз подряд без сбоев).
- [ ] Разбор ошибок понятен без объяснений.
- [ ] Прогресс показывает честные метрики, без придуманных чисел (см. Фазу 3).
- [ ] Все основные экраны визуально консистентны.
- [ ] Мобильная версия работает полноценно.
- [ ] Цены прозрачны, пейволл не блокирует вход целиком.
- [ ] Поддержка доступна (минимум — email/форма с реальным ответом).
- [ ] Ошибки никогда не оставляют пользователя в тупике (везде есть retry/следующий шаг).
- [ ] Оплата надёжна (Stripe webhook проверен на реальных тестовых платежах).
- [ ] Restore/бэкап проверен минимум один раз вручную.
- [ ] Минимум 20 человек прошли бета (Bootcamp + последующие) и есть подтверждённая готовность платить.

Запуск = когда весь список отмечен, не раньше. Если пункт не
выполняется — не вычёркивать «на потом», а решить: либо сделать, либо
осознанно отложить открытие регистрации.

## Критерий готовности фазы

- Чеклист выше пройден целиком.
- Реальные цены зафиксированы в Stripe (не тестовые).
- Публичная регистрация открыта, канал поддержки реально отвечает
  первую неделю после открытия.
