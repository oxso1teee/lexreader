# Фаза 1 — Репозиционирование + бесплатные UI-правила

**Ворота:** нет. Можно начинать сразу после чтения `00-overview.md`.
**Стоимость:** один-два вечера. Ничего не ломает, миграций БД нет.
**Источник:** v1 (смена обещания продукта), v3 §75–150 (правила UI,
которые ничего не стоят).

## Цель фазы

LexReader сейчас говорит о себе как о читалке с карточками. Меняем
формулировку продукта на «система, которая готовит к конкретному
разговору на английском» — без единой новой функции, только тексты
интерфейса и структура акцентов. Плюс применяем горстку бесплатных
UI-правил из v3, которые оказались нарушены при аудите текущего кода.

## 1.1 Landing page — `src/app/landing-page.tsx`

Текущий текст:

```
Учи язык, читая то, что интересно
Никаких упражнений и геймификации. Читай реальные тексты, сохраняй
незнакомые слова одним тапом и повторяй их по расписанию.
```

Заменить на (пример, можно варьировать тон, но держать структуру
«результат → как это работает → CTA», без слов вроде «мощь ИИ»,
«революция», «нового поколения» — прямое правило v3, §115):

```
Готовься к разговору на английском, а не к тесту
Опиши свой проект или вставь вакансию — LexReader соберёт из этого
слова, фразы и короткие тренировки, которые пригодятся в реальном
разговоре, а не в очередном учебнике.
```

Карточки-примеры текстов (A1 «Утро в кофейне» / B1 «Побег из
города») — оставить как есть, они честно показывают библиотеку, но
рядом можно добавить третий пример, ближе к новому позиционированию
(если в системных текстах уже есть что-то про работу/технологии —
использовать его; если нет, эта карточка подождёт до Фазы 5, где
появятся миссии).

CTA `Начать бесплатно` — оставить текст, он уже конкретный и не
хайповый, менять не нужно.

## 1.2 Онбординг — `src/app/onboarding/onboarding-wizard.tsx`

Открыть файл, найти текст первого шага (обычно приветствие/выбор
языка). Применить то же правило: не «какой язык учишь», а какую-то
формулировку, отсылающую к цели — но **не добавлять сейчас поле
«цель»** (goal picker) как отдельный шаг мастера. Это часть Goal
Engine из Фазы 5, преждевременно вводить его здесь без остального
Mission Engine — получится вопрос, ответ на который никуда не ведёт.
На этом шаге меняем только сопроводительный текст экрана, не логику
и не схему `profiles`.

## 1.3 Главная — `src/app/(app)/home/page.tsx`

Аудит по правилу v3 «Today page: один доминирующий CTA» (§79)

(«Learning tip» → «Читай то, что интересно») на соответствие
copywriting-правилу ниже, при необходимости — переформулировать.

## 1.4 Copywriting-правило — зафиксировать как документ

Создать `docs/COPYWRITING.md`:

```markdown
# Правило текста интерфейса

Плохо: «Открой мощь ИИ нового поколения для изучения языков».
Хорошо: «Пройди 7-минутную симуляцию интервью».

Конкретное действие и его результат — всегда лучше абстрактного
превосходства технологии. Перед тем как писать любой новый текст
кнопки/заголовка/пуша, проверь: можно ли заменить на «Открой мощь
X» — если да, переформулируй в сторону конкретного действия и того,
что пользователь получит через N минут.

Источник: v3, раздел «Copywriting rule» (LexReader_Startup_
Master_Plan_v3_Product_UI_Release.md).
```

Этот файл — не код, а ориентир при ревью будущих PR с новыми
текстами (в этой же сессии, при добавлении новых экранов в фазах
5–8, сверяться с ним).

## 1.5 Аудит пустых состояний — `src/components/empty-state.tsx`

Компонент уже реализует правило «иконка + заголовок + текст +
опциональное действие» (сделано в задаче «Единый компонент пустых
состояний» ранее в этом проекте). Дополнительно по правилу v3 §127
(«explains value + one CTA + example») — пройтись по местам вызова
`<EmptyState .../>` (`grep -rn "EmptyState" src/app`) и убедиться,
что `body` каждого вызова не просто говорит «здесь пока пусто», а
даёт конкретный пример действия. Если находится вызов вида «Пока
нет слов» без примера — переформулировать по образцу: «Добавь
первое слово, нажав на любое незнакомое в тексте» вместо «Слов пока
нет».

## 1.6 Тарифы — проверка «не 7 тарифов»

Открыть `src/app/(app)/pricing/page.tsx`. Уже 2 тарифа (месяц/год) —
правилу v3 §133 «не делать 7 тарифов» соответствует. Действие не
требуется, кроме фиксации этого правила в `docs/COPYWRITING.md` (см.
1.4) как ограничения на будущее — при добавлении Career Pack или
Teams (Фаза 11) не расползаться за пределы 3–4 понятных вариантов на
главной странице цен.
