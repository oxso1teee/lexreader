# Фаза 8 — Content-to-Simulation (материал → фразы → миссия)

**Ворота:** Фазы 5–6 работают (есть Mission Engine и хотя бы один
рабочий голосовой сценарий).
**Источник:** v1 §3.4 (Content-to-Simulation pipeline).

## Важное уточнение

v1 описывает этот пайплайн как нечто, что нужно строить с нуля:
«извлечение → очистка → определение языка → …». В LexReader уже
есть большая часть этого — импорт по URL (`src/app/(app)/library/
actions.ts`), YouTube-субтитры (`youtube-actions.ts`), PDF, фото с
OCR (см. задачи #17–20, #78, #92, #95 в истории проекта). Всё это
уже создаёт `texts` с очищенным телом и определённым языком.

**Фаза 8 добавляет только то, чего реально не хватает:** шаг
«извлечь целевые фразы и профессиональные термины из источника» и
кнопку «создать миссию из этого материала» — не новый импорт-пайплайн.

## 8.1 Новый тип источника — вакансия/описание проекта

Текущий импорт заточен под тексты для чтения. Добавить простой ввод
без URL — `src/app/(app)/library/import-plain-text.tsx`: textarea
«Вставь описание вакансии или своего проекта» → создаёт `texts`
строку с `source_type = 'pasted'` (новое значение в существующем enum
`TextSourceType`, `src/lib/types.ts`) напрямую, без парсинга страницы.

## 8.2 Извлечение фраз — `src/lib/phrase-extractor.ts`

Переиспользовать zod-паттерн из `error-extractor.ts` (Фаза 7).
Вход: тело `texts.body`, профессия пользователя. Выход:

```ts
const ExtractedPhraseSchema = z.object({
  phrase: z.string(),
  translation: z.string(),
  relevance: z.enum(["high", "medium", "low"]),
});
```

Не более 15 фраз на источник — цель не «покрыть весь текст», а
выделить то, что реально пригодится в разговоре (термины, устойчивые
конструкции), не каждое незнакомое слово — для этого уже есть
tap-to-translate при обычном чтении, дублировать не нужно.

## 8.3 Кнопка «Создать миссию из этого материала»

На странице источника (`src/app/(app)/library/[textId]` или где
сейчас показывается прочитанный текст) — новая кнопка, видна только
если у пользователя есть активная цель (`goals`, Фаза 5) без
привязанной миссии. Действие: извлечь фразы (8.2), создать `missions`
+ `mission_steps` (используя шаблон, соответствующий `goals.type`
пользователя), где `target_phrases` первого этапа = самые релевантные
извлечённые фразы. Это именно то отличие от обычного импорта, которое
обещано в позиционировании Фазы 1 — «загрузи вакансию, получи
программу», а не просто ещё один текст в библиотеке.

## 8.4 Что НЕ делать в этой фазе

- Не подключать `spaCy`/`Stanza`/`Unstructured` — для английского как
  единственного изучаемого языка (см. ограничение v1 §4.16)
  достаточно LLM-извлечения из 8.2, отдельный NLP-пайплайн избыточен
  до появления второго изучаемого языка.
- Не строить video-file/audio-file импорт с WhisperX — это отдельный
  большой кусок (offline transcription + alignment), не связан
  напрямую с целью этой фазы (текстовые источники → фразы → миссия).
  Если понадобится — отдельная будущая фаза, не часть этой.

## Критерий готовности фазы

- Вставленный текст вакансии создаёт `texts` строку.
- Кнопка «Создать миссию» на источнике реально создаёт миссию с
  релевантными `target_phrases`, проверено вручную на 3 разных
  вакансиях/описаниях проектов — фразы должны быть по существу
  разными, не одним и тем же шаблонным набором.
- Не более 15 фраз извлекается за раз (лимит соблюдается).
- `npx tsc --noEmit`/`eslint` чисто, задеплоено, проверено на проде.
