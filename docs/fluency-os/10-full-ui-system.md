(дизайн-система с 30 компонентами и visual regression тестами имеет
смысл там, где несколько разработчиков должны не разъезжаться
визуально — для одного человека, пишущего каждый экран самостоятельно,
достаточно текущей дисциплины: общие токены в `globals.css`,
переиспользуемые компоненты вроде `EmptyState`/`ScreenHeader`).

Это самый объёмный и самый необязательный слой из всех трёх
документов. Записан подробно как справочник на будущее — если

## 10.1 Что уже примерно есть vs что добавляет v3

Уже есть (см. `src/app/globals.css`, `src/components/`): токены цвета
(caramel/beige/accent-*), общий `ScreenHeader`, `EmptyState`, нижняя
навигация с 5 пунктами (v3 требует максимум 6 — уже соблюдено).

v3 добавляет: формальный список токенов (spacing/radius/shadow/motion/
z-index/breakpoints — сейчас часть из этого просто «в голове», не
зафиксирована), 30 именованных компонентов (Button/Dialog/Toast/
MetricCard/SessionCard и т.д.) на базе shadcn/ui + Radix, Storybook
для документации компонентов, Chromatic/Playwright screenshot diffing
для visual regression, командную палитру (Cmd+K), глобальный поиск,
changelog/roadmap/help center как отдельные разделы, ~70 маршрутов
суммарно (маркетинг + приложение + аккаунт + поддержка + админка).

## 10.2 Порядок внедрения (если/когда дойдёт)

Из v3 §143 (UI implementation order), адаптировано:

1. Аудит текущих маршрутов, дедупликация, карта информационной архитектуры.
2. Токены + layout-правила (сайдбар/топбар для десктопа — сейчас
   мобильная нижняя навигация, десктопная версия ещё не нужна, пока
   основная аудитория заходит с телефона).
3. Основной цикл — Today/Mission/Session/Feedback/Review (в основном
   уже построен в Фазах 1–7, здесь — приведение к единой системе
   компонентов).
4. Library/Reader/Errors/Progress.
5. Settings/Billing/Notifications/Help.
6. Landing/Pricing/Demo/Changelog/Roadmap/Legal.

## 10.3 Полный список новых UI-паттернов из v3 (справочно)

Command palette, global search, changelog/roadmap/feedback boards,
достижения без фейковой срочности (уже частично реализовано —
стрик с заморозкой, задача «Достижения, квест недели, заморозка
стрика» в истории проекта), реферальная система, shareable-карточки
результата (частично есть — карточка прогресса в share-card route),
demo mode без регистрации, weekly report, drip-сообщения против
оттока (day 2/7/21). Все — см. мокапы в разделе «Ещё UI-паттерны из
v3» артефакта `docs/FLUENCY_OS_VISION_ALL3_2026-07-31.html`.
