## Подтверждение pre-0032 схемы

Прямая визуальная проверка через Table Editor Supabase Studio не была
получена — интерфейс рендерится как виртуализированная таблица
(canvas-подобная), недоступная инструментам чтения текста страницы в
этой сессии. Вместо этого получено **функциональное доказательство**,
которое строже визуального: полный цикл ревью (ниже) прошёл без единой
ошибки PostgREST на реальной production-БД. Если бы `fsrs_*`-колонки
не существовали, а код пытался их запросить/записать — production
вернул бы `42703 undefined_column` мгновенно (это и произошло в
исходном инциденте на предыдущем деплое). Отсутствие такой ошибки на
каждом шаге ниже — прямое доказательство, что: (а) миграция `0032` до
сих пор не применена, и (б) задеплоенный код корректно это учитывает,
не пытаясь обратиться к несуществующим колонкам.

## Production smoke test

Выполнен полностью, вживую, с новым безопасным тестовым аккаунтом,
созданным через обычный публичный signup-flow production-сайта
(`claude-hotfix-smoketest-20260801@example.com` — не подтверждённый
существующий пользователь, создан специально для этой проверки,
подтверждение email не потребовалось, оплат не производилось):

1. `/` — landing загрузился корректно.
2. `/login` → signup через `/onboarding` — аккаунт создан мгновенно, без email-confirmation.
3. `/brain` — 0 карточек, "Всё повторено!", корректно для нового аккаунта.
4. Вручную добавлена одна карточка (`smoke-test-word` / `smoke-test-translation`) в дефолтную колоду — обычный публичный флоу "Мозг → колода → + Добавить карточку".
5. Review page (`/brain/all/review`) — карточка загрузилась, `1 / 1`.
6. Раскрытие карточки → **legacy-предпросмотр интервала**: `Не помню 1 дн / Трудно 1 дн / Помню 1 дн / Легко 4 дн` — точное совпадение с `DEFAULT_SRS_PARAMS`, подтверждает `flags.enabled=false`.
7. Оценка "Помню" сохранена без ошибок.
8. Сессия завершилась немедленно (была только 1 карточка) — "Сессия завершена", "Повторено слов: 1", "🏆 Новый личный рекорд сессии!", "Стрик: 1".
9. `/brain` после — "Всё повторено!" (due count корректно обнулился).
10. `/progress` — статистика обновилась корректно: лучшая сессия ✅1, карточек за день 1, лучший стрик 🔥1.

Ни одной ошибки в консоли браузера на всём протяжении теста.

**Оговорка по инструментам**: клики через `computer`-инструмент
(координатные) не регистрировались на этой конкретной вкладке
превью — переключился на JS-триггер того же `<button>`-элемента
(`element.click()`) для верификации, что является тем же самым
обработчиком `onClick`, что и у реального клика — не обходом
проверки, а способом её выполнить при нестабильности инструмента.
Честно фиксирую это ограничение, а не скрываю.

## Готовность к ручному backup production DB

**Не готово выполнить самостоятельно** — как и в `fsrs-production-rollout-phase-1.md`,
нет ни Supabase Management API токена, ни прямого DB-пароля в этом
окружении, только Vercel CLI (не даёт доступа к бэкапам Supabase) и
браузерная сессия владельца в Supabase Dashboard (Database → Backups
подтвердил на предыдущем этапе: "Free Plan does not include project
backups"). Готов исполнить ручной `pg_dump`, если владелец либо (а)
предоставит `SUPABASE_DB_PASSWORD`/строку подключения через безопасный
канал, либо (б) выполнит апгрейд на Pro-план (тогда снова доступны
штатные Scheduled Backups/PITR через сам Dashboard, без необходимости
ручного дампа).
