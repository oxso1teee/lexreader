## 0. TL;DR — если читать только один раздел

Топ-7 вещей, которые нужно закрыть до того, как звать реальных людей тестировать:

1. **Любой залогиненный пользователь может выдать себе Premium навсегда бесплатно — не кнопкой, а напрямую через Supabase API**, в обход Stripe вообще. Это не баг кнопки "Начать" (это тоже баг, см. №3), а дыра в правилах доступа к базе данных. Работает уже сейчас и продолжит работать даже после подключения настоящего Stripe. → [раздел 2.1](#21-любой-пользователь-может-выдать-себе-premium-через-прямой-api-запрос-критично)
2. **Фото-OCR импорт слов полностью сломан на проде** — блокируется нашими же security-заголовками (CSP). Пользователь видит "Обрабатываем…" и ничего не происходит. → [раздел 2.3](#23-фото-ocr-импорт-полностью-сломан-на-проде-критично)
3. **YouTube Watch Mode (видео + субтитры) полностью сломан на проде** — та же причина (CSP блокирует загрузку youtube.com/iframe_api). Это твоя любимая фича судя по прошлым сессиям. → [раздел 2.4](#24-youtube-watch-mode-полностью-сломан-на-проде-критично)
4. **В приложении нет ни одной страницы обработки ошибок** (`error.tsx`) — любая мелкая сетевая заминка на середине действия (удаление колоды, повторение карточки, сохранение прогресса) роняет экран в белый "Application error" без кнопки "назад" или "попробовать снова". → [раздел 2.5](#25-нет-ни-одного-error-boundary-критично)
5. **Колоды нельзя удалить из интерфейса вообще** — функция в коде есть, кнопки нигде нет. Бесплатный пользователь с лимитом 3 колоды, создав 3, застревает навсегда. → [раздел 2.6](#26-нельзя-удалить-колоду-из-интерфейса-критично)
6. **Твой баг "не запоминает аккаунт"** — найден и уже исправлен в этой сессии (см. [раздел 1.1](#11-не-запоминает-аккаунт--причина-найдена-уже-исправлено)).
7. **Твой баг "подписка выдаётся просто так"** — причина глубже, чем казалось: не просто отсутствие ключа Stripe. См. [раздел 1.2](#12-подписка-выдаётся-без-оплаты--причина-найдена-нужен-полноценный-фикс).

Дальше — полный список: 7 критичных, ~20 высокого приоритета, дальше средние и мелкие плюс список того, что уже подтверждено рабочим.

## 1. Баги, которые ты нашёл сам

### 1.1 "Не запоминает аккаунт" — причина найдена, уже исправлено

Проверил напрямую: механизм обновления сессии (`src/proxy.ts`) написан правильно и подтверждён рабочим — протестировал через настоящий перезапуск браузера (сохранил cookies, открыл в новом изолированном контексте) — сессия восстанавливается корректно, редиректит на `/home`, а не на `/onboarding`.

Реальная причина твоего опыта: когда ты тестировал регистрацию, `mailer_autoconfirm` был выключен, а письмо подтверждения не могло дойти (Supabase-почта по умолчанию отклоняет `example.com`-подобные адреса и жёстко лимитирована; Resend без верифицированного домена шлёт только на твой собственный e-mail). Аккаунт создавался, но оставался неподтверждённым — и `signInWithPassword` отклонял вход **с тем же общим сообщением "Неверный email или пароль"**, что и для настоящей неверной пары логин/пароль (это специально сделано так — раздел 2.10, чтобы не палить существование аккаунта). Выглядело так, будто приложение "не помнит" — на деле аккаунт был, просто вход в него для неподтверждённого email отклонялся молча под тем же текстом ошибки.

Уже исправлено в этой сессии: `mailer_autoconfirm: true` включен на проде — новые регистрации подтверждаются мгновенно, без письма.

**Не до конца устранённый смежный риск**: раз ошибка "неверный email или пароль" используется для ЛЮБОЙ причины отказа входа (что правильно с точки зрения защиты от перебора), у пользователя с настоящей опечаткой в пароле и у пользователя с этой (уже устранённой) проблемой будет один и тот же непонятный текст. Отдельно от этого — [раздел 3.9](#39-регистрация-без-rate-limit--протечка-факта-существования-аккаунта-высокий) описывает, что сама регистрация (`/onboarding`) **не имеет** такой защиты и показывает сырые ошибки Supabase.

### 1.2 "Подписка выдаётся без оплаты" — причина найдена, нужен полноценный фикс

Ты абсолютно прав, но причина куда глубже, чем просто "не настроен Stripe":

**Слой 1 (то, что ты увидел)**: `STRIPE_SECRET_KEY` не задан → `isStripeConfigured()` возвращает `false` → страница `/pricing` показывает кнопку "Начать", которая вызывает `simulateSubscribe` — тестовую заглушку для локальной разработки, которая мгновенно ставит `status: 'active'` без всякой оплаты. Файл: `src/app/(app)/pricing/actions.ts:110-130`.

**Слой 2 (гораздо серьёзнее — сам не заметил бы через простой клик)**: даже если сейчас настроить настоящий Stripe, дыра останется — потому что:
- Правило доступа к таблице `subscriptions` в базе данных (`supabase/migrations/0001_init.sql:145-146`) разрешает **любому залогиненному пользователю писать в свою собственную строку** без ограничений на то, какие поля можно менять. Это значит: пользователь может открыть консоль браузера и напрямую обратиться к Supabase API (публичный anon-ключ уже есть в коде страницы), выставив себе `plan: 'premium_yearly', status: 'active'` — без единого клика по кнопке "Начать", без Stripe, без нашего кода вообще.
- `simulateSubscribe` сам по себе тоже не проверяет, настроен ли Stripe — эта функция остаётся вызываемой напрямую (Server Actions в Next.js доступны как отдельные конечные точки независимо от того, показывается ли кнопка в интерфейсе), так что даже после подключения Stripe кто-то технически подкованный сможет вызвать её напрямую и получить бесплатный доступ.

Это самая серьёзная находка всего аудита — детали и точный план исправления в [разделе 2.1](#21-любой-пользователь-может-выдать-себе-premium-через-прямой-api-запрос-критично) и [2.2](#22-simulatesubscribe-можно-вызвать-напрямую-даже-после-настройки-stripe-критично).

## 2. КРИТИЧНО — закрыть до реального запуска

### 2.1 Любой пользователь может выдать себе Premium через прямой API-запрос (КРИТИЧНО)

**Файл**: `supabase/migrations/0001_init.sql:145-146`
```sql
create policy "subscriptions: owner full access" on subscriptions
  for all using (owner_id = auth.uid()) with check (owner_id = auth.uid());
```
плюс `grant select, insert, update, delete on ... subscriptions ... to authenticated;` (строки 157-160).

**Сценарий**: любой залогиненный пользователь, открыв консоль браузера (публичный anon-ключ уже есть в JS-бандле страницы, `src/lib/supabase/client.ts`), выполняет:
```js
await supabase.from('subscriptions').upsert({
  owner_id: '<свой uid>', plan: 'premium_yearly', status: 'active',
  current_period_end: '2099-01-01'
})
```
и получает Premium навсегда. Работает **уже сейчас**, и продолжит работать **после** подключения настоящего Stripe — комментарий в `src/app/api/webhooks/stripe/route.ts:7-8` ("вебхуки — единственный источник истины") на деле ничем не подкреплён: сама база разрешает пользователю писать в эту таблицу напрямую.

**Побочный эффект той же дыры**: `createBillingPortalSession` (`pricing/actions.ts:77-102`) доверяет полю `stripe_customer_id`, прочитанному из базы, и передаёт его прямо в Stripe API. Если пользователь узнает чужой `stripe_customer_id` (например, из письма/квитанции), он может прописать его себе через ту же дыру и открыть чужой Customer Portal (посмотреть счета, отменить чужую подписку).

**Как чинить**: новая миграция, сужающая политику:
```sql
drop policy "subscriptions: owner full access" on subscriptions;
create policy "subscriptions: owner read only" on subscriptions
  for select using (owner_id = auth.uid());
-- никаких insert/update/delete для authenticated — всё через service_role
-- (уже используется в вебхуке и должно использоваться в simulateSubscribe, см. 2.2)
revoke insert, update, delete on subscriptions from authenticated;
```
Это тот же паттерн, что уже правильно сделан для `auth_attempts` (там вообще нет policy для `authenticated`, только service_role).

### 2.2 `simulateSubscribe` можно вызвать напрямую даже после настройки Stripe (КРИТИЧНО)

**Файл**: `src/app/(app)/pricing/actions.ts:110-141`

`simulateSubscribe`/`cancelSimulatedSubscription` не проверяют `isStripeConfigured()` вообще — в отличие от `createCheckoutSession` в том же файле (строка 25), где такая проверка есть. Ограничение "какая кнопка показывается" — чисто визуальное, на уровне `pricing/page.tsx`; сама server action остаётся вызываемой напрямую независимо от того, что видно в интерфейсе.

**Как чинить**: добавить в начало обеих функций:
```ts
export async function simulateSubscribe(plan: ...) {
  if (isStripeConfigured()) {
    return; // или throw — в проде с настоящим Stripe эта заглушка не должна работать
  }
  ...
}
```
Также используют обычный RLS-клиент (`createClient()`, не `createServiceClient()`) — после фикса 2.1 (сужения RLS-политики) эта функция **перестанет работать вообще**, пока её явно не переключат на service-role клиент. Это нормально и даже полезно — но нужно решить: оставить `simulateSubscribe` для локальной разработки (тогда переключить на `createServiceClient()` и добавить проверку выше, чтобы не работала в проде), или вовсе убрать из продакшен-сборки.

### 2.3 Фото-OCR импорт полностью сломан на проде (КРИТИЧНО)

**Файлы**: `next.config.ts:8-17` (CSP) vs `node_modules/tesseract.js/src/worker/browser/defaultOptions.js:11`, `.../getCore.js:14`, `.../worker-script/index.js:130`

Tesseract.js по умолчанию грузит воркер, wasm-модуль распознавания и файлы обученных данных языка с `cdn.jsdelivr.net`. Наш CSP (`script-src`/`connect-src` в `next.config.ts`) этот домен нигде не разрешает. Вызовы `createWorker(...)` в `src/app/(app)/brain/import-modal.tsx:107` и `src/app/(app)/library/new/photo-import-form.tsx:36` не переопределяют пути на свой домен — значит браузер молча блокирует загрузку воркера/моделей по CSP.

**Что видит пользователь**: нажимает "Импорт по фото", видит "Обрабатываем…" и зависание/ошибку в консоли, которую никогда не увидит сам.

**Как чинить** (два варианта):
- Быстрее: добавить `cdn.jsdelivr.net` в `script-src`/`connect-src`/`worker-src` в CSP.
- Правильнее: скачать worker.min.js/core/traineddata в `public/tesseract/` и передать `workerPath`/`corePath`/`langPath` в `createWorker(...)`, указывая на свой домен (тогда CSP не нужно ослаблять для стороннего CDN).

### 2.4 YouTube Watch Mode полностью сломан на проде (КРИТИЧНО)

**Файлы**: `next.config.ts:10` (CSP `script-src`) vs `src/app/watch/[textId]/watch-player.tsx:100-104`

```ts
const tag = document.createElement("script");
tag.src = "https://www.youtube.com/iframe_api";
document.body.appendChild(tag);
```
`script-src` в CSP не включает `https://www.youtube.com` — загрузка этого скрипта блокируется браузером, `window.YT` никогда не появляется, плеер не создаётся. Примечательно: `frame-src https://www.youtube.com` в CSP уже есть (для самого iframe), но это не помогает — сначала блокируется загрузочный script, до создания iframe дело не доходит.

**Что видит пользователь**: открывает "Смотреть" на YouTube-тексте — видео-блок остаётся чёрным/пустым навсегда, транскрипт снизу при этом рендерится нормально, что ещё больше сбивает с толку (непонятно, сломано приложение или видео).

**Как чинить**: добавить `https://www.youtube.com` в `script-src` в `next.config.ts`.

### 2.5 Нет ни одного error boundary (КРИТИЧНО)

**Проверено**: полный рекурсивный поиск по `src/app` — ни одного `error.tsx`, `loading.tsx`, `not-found.tsx`, `global-error.tsx` нет вообще.

Любой server action, который делает `throw new Error(...)` при ошибке (таких много: `deleteText`, `deleteDeck`, `deleteFlashcard`, `deleteWord`, `markKnown`, `reviewWord`, `setWordLevel`, `finishReading`, `updateTextProgress` и другие), при реальном сбое (кратковременная недоступность БД, таймаут) роняет **весь экран** в стандартный "Application error" Next.js — без кнопки "назад", без "попробовать снова", на английском.

Также нет `loading.tsx` — на медленном мобильном соединении экран, ожидающий данные с сервера (например `/progress`, который делает 8 параллельных запросов), просто "замирает" на предыдущем состоянии без какого-либо индикатора загрузки.

**Как чинить**: добавить хотя бы один общий `src/app/(app)/error.tsx` (с кнопкой "Обновить страницу" / "На главную") и `src/app/error.tsx` для верхнего уровня — это покрывает 90% случаев одним файлом каждый. `loading.tsx` — по желанию на самых тяжёлых экранах (`/progress`, `/library`).

### 2.6 Нельзя удалить колоду из интерфейса (КРИТИЧНО)

**Файл**: `src/app/(app)/brain/actions.ts:39-44` — функция `deleteDeck` существует, но не вызывается **нигде** ни в одном `.tsx`-файле (проверено грепом по всему `src/`). Ни `deck-card.tsx`, ни `[deckId]/page.tsx` не показывают кнопку удаления.

**Сценарий**: при регистрации автоматически создаётся "Основная колода" (`onboarding/actions.ts:54-56`), которая уже засчитывается в лимит `FREE_DECK_LIMIT=3` (`src/lib/subscription.ts:8`). Бесплатный пользователь создаёт ещё 2 колоды (например, тестовые/ошибочные) — упирается в лимит навсегда, без единого способа освободить место, кроме как заплатить за Premium. Это выглядит как явный, обидный дефект прямо в момент, когда пользователь пытается разобраться в приложении.

**Как чинить**: добавить кнопку удаления (с подтверждением) на карточку колоды или на страницу колоды — переиспользовать паттерн подтверждения удаления, уже сделанный для текста в библиотеке (`text-card.tsx:76-86`).

### 2.7 Условия использования и Настройки — несоответствие и мёртвый контакт (КРИТИЧНО для реального запуска, не для теста на друзьях)

**Файлы**: `src/app/terms/page.tsx:29-36,74`, `src/app/privacy/page.tsx:87`, `src/app/(app)/pricing/page.tsx:103-131,180`

Два отдельных, но связанных пункта:
1. Раздел "Подписка и оплата" в Условиях описывает **настоящую** периодическую оплату через Stripe ("Платная подписка продлевается автоматически... доступ сохраняется до конца оплаченного периода"). На деле сейчас нажатие "Начать" рядом с настоящими ценами (449₽/мес, 4490₽/год) не проводит вообще никакой оплаты (см. раздел 1.2/2.1/2.2) — только маленькая подпись под ценами намекает, что это тестовый режим. ## 3. ВЫСОКИЙ приоритет

### Безопасность и абьюз

#### 3.1 Общий кэш переводов может быть отравлен любым пользователем (высокий)
**Файл**: `supabase/migrations/0001_init.sql:149-152` — `insert to authenticated with check (true)`, без всякой валидации содержимого. Из-за `unique(source_text, source_lang, target_lang)` и `ignoreDuplicates: true` в коде приложения (`api/translate/route.ts:46-51`) первая вставленная строка побеждает навсегда — приложение никогда не перезаписывает существующую запись кэша. Пользователь может напрямую вставить неверный/оскорбительный перевод для распространённого слова раньше, чем это сделает настоящий запрос — и все последующие пользователи (включая платных) будут получать испорченный перевод постоянно.

#### 3.2 Таблицу лимита переводов пользователь может стереть сам себе (высокий)
**Файлы**: `supabase/migrations/0009_translate_rate_limit.sql:15-19`, `src/app/api/translate/route.ts:9-26` — политика `for all` (не только `insert`) плюс `grant ... delete`. Пользователь может напрямую вызвать `DELETE` по своим же записям в `translate_requests`, обнулив историю лимита, и продолжать слать запросы без ограничения 30/мин — в отличие от `auth_attempts` (`0011_auth_rate_limit.sql`), где для `authenticated` вообще нет политики (правильный паттерн).

#### 3.3 Гонка при проверке лимита переводов (высокий)
**Файл**: `src/app/api/translate/route.ts:9-26` — подсчёт количества запросов и вставка новой записи не атомарны (сначала `select count`, потом `insert`). Много параллельных запросов подряд (например, 100 одновременных fetch) обходят лимит 30/мин, так как каждый читает счётчик до того, как остальные успели вставить свои записи.

#### 3.4 SSRF: проверка публичного IP обходится через HTTP-редирект (высокий)
**Файлы**: `src/lib/ssrf-guard.ts`, `src/app/(app)/library/actions.ts:136-140` — `assertPublicUrl()` проверяет только исходный URL, а `fetch(url, { redirect: "follow" })` дальше следует за редиректами без повторной проверки. Пользователь может импортировать "статью по ссылке", указывающую на публичный URL, который отвечает 302-редиректом на внутренний адрес (например, cloud-metadata `169.254.169.254`) — защита это не ловит вообще.

**Как чинить**: `fetch(..., { redirect: "manual" })` + вручную проверять каждый `Location`-заголовок через `assertPublicUrl` перед тем, как следовать дальше (с ограничением числа переходов).

#### 3.5 Health-check эндпоинт без авторизации жрёт общую квоту перевода (высокий)
**Файл**: `src/app/api/health/translate/route.ts:7-26` — никакой аутентификации, никакого рейт-лимита, в отличие от настоящего `/api/translate`. `docs/OBSERVABILITY.md` прямо советует опрашивать этот URL внешним мониторингом каждые несколько минут — это уже само по себе способ незаметно съедать общий дневной лимит MyMemory (~5000 слов/день на всё приложение).

#### 3.6 Вебхук Stripe не обрабатывает `customer.subscription.updated` (высокий)
**Файл**: `src/app/api/webhooks/stripe/route.ts` — switch покрывает только `checkout.session.completed`/`invoice.paid`/`invoice.payment_failed`/`customer.subscription.deleted`. Смена плана через Customer Portal (месяц→год, отложенная отмена) присылает именно `customer.subscription.updated`, который сейчас молча игнорируется — план в базе останется неверным до следующего `invoice.paid`.

#### 3.7 Вебхук всегда пишет `status: "active"`, не читая настоящий статус из Stripe (средне-высокий)
**Файл**: `src/app/api/webhooks/stripe/route.ts:47-58` — получает объект подписки из Stripe (у него есть собственное поле `.status`, например `incomplete`/`trialing`), но игнорирует его и жёстко пишет `"active"`.

#### 3.8 Регистрация без rate-limit + протечка факта существования аккаунта (высокий)
**Файл**: `src/app/onboarding/actions.ts:10-59` — в отличие от `login`/`requestPasswordReset` (которые используют `isAuthAttemptAllowed`/`logAuthAttempt` и одинаковый ответ независимо от существования email), регистрация не ограничена по частоте вообще и показывает сырое сообщение Supabase (`signUpError.message`) — если Supabase возвращает разные тексты для "уже зарегистрирован" и других ошибок, это прямой канал проверки существования аккаунтов + возможность скриптовать массовую регистрацию/спам.

## 4. СРЕДНИЙ приоритет

- **Grace-период после неудачного списания пропадает, если `current_period_end` пуст** (`src/lib/subscription.ts:27-31`) — при событии, пришедшем не по порядку, пользователя мгновенно откатывает на free вместо обещанных 3 дней отсрочки.
- **`CRON_SECRET` при отсутствии переменной сравнивается со строкой `"Bearer undefined"`** (`api/cron/push-reminders/route.ts:27-30`) — если переменная случайно не задана, любой, кто пришлёт заголовок `Authorization: Bearer undefined`, запустит массовую рассылку пушей. Нужно явно проверять, что `CRON_SECRET` вообще задан.
- **Действия Stripe в `pricing/actions.ts` не обёрнуты в try/catch** (`customers.create`, `checkout.sessions.create`, `billingPortal.sessions.create`) — сбой Stripe API роняет страницу вместо показа понятной ошибки, хотя механизм для этого (`state.error`) уже есть.
- **Симулированная подписка может "пережить" включение настоящего Stripe** — строка, созданная через `simulateSubscribe` (без `stripe_customer_id`, но с `provider: 'stripe'`), продолжит действовать весь свой срок (30/365 дней) даже после того, как настоящий Stripe заработает; нет миграции/очистки тестовых подписок перед реальным запуском.
- **`/reset-password/confirm` не отличает "сессию восстановления пароля" от обычной сессии** (`reset-password/confirm/page.tsx:5-9`) — на чужом/публичном устройстве, где кто-то уже залогинен, можно зайти на этот URL и сменить пароль без повторного ввода текущего.
- **Не проверяется ошибка создания дефолтной колоды при регистрации** (`onboarding/actions.ts:54-56`) — если вставка не удаётся, пользователь попадает на `/home` без колоды, и позже "добавить слово из читалки в колоду по умолчанию" сломается с "Основная колода не найдена".
- **Онбординг может стать вечным тупиком**, если вставка в `profiles` не удаётся (RLS-заминка, повторный сетевой запрос) — `getProfile()` будет вечно возвращать `null`, а повторная попытка регистрации того же email упрётся в сырую ошибку Supabase "уже зарегистрирован" — пользователь не сможет попасть в приложение вообще.
- **"Изучаются (ур. 1-3)" на статистике на самом деле включает и совсем непросмотренные слова** (`progress/page.tsx:70-74`, `.neq("status", "known")` вместо явной фильтрации по уровню) — завышает реальный прогресс.
- **Все "дневные" границы (лимит слов, стрик, куча активности, время пуш-напоминаний) считаются по UTC сервера, а не по времени пользователя** — у пользователей в дальних часовых поясах может ложно сбрасываться/задваиваться стрик, а пуш "не теряй стрик" приходит посреди ночи.
- **Множественный выбор в Мозге может выродиться в один вариант ответа**, если в колоде всего 1-3 карточки (частый случай в первый день использования) — `buildOptions` берёт "неправильные" варианты только из карточек текущей сессии.
- **Мультивыбор ответов (Multiple Choice) при этом же условии — угадать невозможно не ошибиться**: с одним вариантом кнопка "правильная" всегда одна и та же.
- **CSV-импорт карточек всё ещё наивный** — не понимает запятые в кавычках (`brain/import-modal.tsx:36-37`), перевод с запятой внутри ломает колонки.
- **Нет проверки диапазона для настроек SRS** (`brain/settings/actions.ts:12-42`) — можно сохранить отрицательные/нулевые дневные лимиты, `NaN` при пустом поле.
- **CSP разрешает `ws:`/`wss:` на ЛЮБОЙ хост** (`next.config.ts:14`) — задумано только для локальной разработки (HMR), но действует и в проде, ослабляя защиту от эксфильтрации данных через XSS.
- **Нет заголовка HSTS** (`next.config.ts`) — оставляет окно для атак понижения протокола при первом визите.
- **Не задан `maxDuration` ни на одном роуте** — импорт по URL и YouTube делают последовательные внешние запросы (до ~20 сек суммарно), что рискует упереться в лимит выполнения функций на Hobby-плане Vercel без явного логирования причины.
- **Импорт по фото в Мозге (`import-modal.tsx`) не показывает прогресс распознавания**, в отличие от аналогичного места в библиотеке — просто статичный текст "Обрабатываем…".
- **Заголовок ошибки перевода "Unauthorized" (401) показывается на английском** прямо в интерфейсе чтения, если сессия истекла посреди долгого чтения.
- **Пустое состояние Тетради одинаковое для "тетрадь реально пуста" и "по фильтру/поиску ничего не найдено"** — вводит в заблуждение пользователя с непустым словарём.

## 5. НИЗКИЙ приоритет / полировка

- Touch-таргеты меньше 44px, не попавшие в прошлый проход: кнопки удаления карточки (`card-row.tsx`, `import-modal.tsx`), кнопка удаления текста (~40px), кнопка отправки новой карточки, переключатель направления изучения, кнопки "Уже знаю"/"Удалить" в Тетради, кнопка "Завершить ✓" в читалке, переключатели вкладок импорта/режимов повторения, тумблеры "Показывать таймер"/"Автопроигрывание" (24px), шестерёнка настроек в шапке (36px), кнопка "+" добавления слова (36px vs правильные 56px в библиотеке).
- Наведение-только взаимодействие: числа активности в тепловой карте видны только через `title` (не работает на тач-устройствах).
- Кликабельные `<div>` без `role="button"`/`tabIndex` в списке сегментов субтитров — недоступны с клавиатуры.
- Декоративный кружок-аватар в шапке выглядит кликабельным, но ничего не делает.
- Статус уровня слова в тексте читалки различается только цветом — нет доп. иконки/паттерна для дальтоников (в самом попапе перевода уровень уже дублируется текстом — это касается только подсветки внутри текста).
- Иконка загрузки фото (📷) без `aria-label`.
- Офлайн-страница — тупик без кнопки "Повторить"/ссылки на главную.
- Онбординг: на последнем шаге (регистрация) нет кнопки "Назад".
- Кэш переводов не удаляется никогда (нет TTL/очистки, в отличие от таблиц лимитов) — не срочно при нынешнем масштабе.
- `importFlashcards` не проверяет, что `deckId` принадлежит вызывающему пользователю, до вставки (перекрыто RLS на чтение, но создаёт "осиротевшие" по смыслу записи).
- Дублирующиеся карточки при повторном импорте одного файла — нет проверки на дубликаты.
- Storage MIME-проверка смотрит только на заголовок `Content-Type`, не на реальное содержимое файла (подмена возможна через прямой API-вызов, не через обычную загрузку в интерфейсе).
- `auth/callback`: параметр `next` не сверяется со списком разрешённых путей (защита от открытого редиректа частичная).
- Игровые поля профиля (стрик, цель в день) можно менять произвольно напрямую через REST — сейчас без последствий, но стоит учесть при будущих лидербордах.
- Устаревший текст в форме импорта YouTube ("уберём таймкоды") — на деле таймкоды теперь сохраняются, текст не обновили после рефакторинга Watch Mode.
- Ручной перевод (введённый руками при сбое API) не сохраняется в общий кэш — при повторном открытии того же слова/фразы придётся вводить заново.
- Сравнение кэша переводов регистрозависимое ("Hello" ≠ "hello").
- Ручное сравнение слов через `.ilike()` без экранирования `%`/`_` — слово вроде "50%" может случайно "склеиться" с несвязанной записью.
- Скрипт YouTube IFrame API повторно вставляется в DOM при каждом монтировании компонента без проверки, что он уже есть.
- Нет верхней границы на длину вставляемого вручную текста в библиотеке.
- Разбиение на предложения не учитывает сокращения ("Mr.", "Dr.") — обрезает контекст слова неверно.
