# Идеи для развития LexReader — по скриншотам Lexpring (2026-07-24)

Разбор 10 скриншотов конкурентного приложения (Lexpring — того самого, чью
идею мы изначально клонировали, см. `project_lexreader` в памяти). Цветовая
палитра/тема НЕ рассматривается — только функциональные идеи, применимые
к нашей архитектуре. По каждому пункту: что это, зачем нужно, что у нас уже
есть/чего не хватает, куда именно в коде это ляжет, примерная сложность.

Это план для обсуждения, а не готовое ТЗ на исполнение — нужно решить, что
из этого действительно ценно для наших пользователей, прежде чем делать.

---

## 1. Коллекции для многочастевых текстов (книги/сериалы) — ВЫСОКИЙ приоритет

**Что видно на скрине:** при импорте статьи по URL есть выпадающий список
"Колекція" (в примере — "Идиот"), куда можно добавить импортируемый текст.
Так пользователь сам вручную группирует главы одной книги под одним
названием, вместо того чтобы приложение пыталось угадать и склеить все
страницы автоматически.

**Почему это важнее, чем наш текущий фикс с `rel="next"`:** мы сейчас
пытаемся автоматически ходить по ссылкам "далее" при импорте по URL
(`src/app/(app)/library/actions.ts`, `findNextPageUrl`) — это работает для
части сайтов (подтверждено на Royal Road), но никогда не сработает для
сайтов на JS-фреймворках без серверных ссылок между страницами (подтверждено
на liteka.ru — и что важно, у самого Lexpring есть точно такое же
предупреждение в интерфейсе: "Сайти з важким JavaScript можуть не
підтримуватися" — это ИХ собственное ограничение тоже, не только наше).
Коллекции решают проблему не автоматизацией парсинга, а организацией: раз
одну страницу — вопрос решаем, а десятки глав пользователь всё равно
предпочтёт добавлять по одной (у него есть время, у бота — нет), но видеть
их не как раскиданный список разрозненных текстов, а как один прогресс-бар
по всей книге.

**Что нужно:**
- Новая таблица `collections` (id, owner_id, title, language) + колонка
  `texts.collection_id` (nullable, `references collections(id)`).
- В [library actions](../src/app/(app)/library/actions.ts) — при импорте
  (ручной/URL/YouTube/фото) добавить опциональный выбор существующей
  коллекции или создание новой прямо из формы.
- [Library screen](../src/app/(app)/library/page.tsx) — группировать тексты
  одной коллекции визуально (как папка/серия), с общим прогрессом
  (сумма/среднее по `text_progress` всех текстов коллекции) и общим
  "последнее чтение".
- Кнопка "Продолжить" в коллекции — открывает следующий непрочитанный текст
  коллекции, а не конкретный.

**Сложность:** средняя — новая таблица + миграция, изменения в 3-4 местах
UI, но без внешних интеграций и хрупкого парсинга.

## 2. Импорт PDF — СРЕДНИЙ приоритет, низкая сложность

**Что видно:** отдельная вкладка "PDF" в форме импорта, наравне с YouTube/
URL/Текст/TikTok.

**Почему стоит сделать:** в отличие от YouTube-скрапинга или JS-сайтов, PDF
— это НЕ антибот-проблема и НЕ JS-рендеринг: текст обычно уже лежит в файле
структурированно. Библиотека `pdfjs-dist` (используется Mozilla/Firefox для
встроенного PDF-вьюера, бесплатная, без серверных ограничений) умеет
вытащить текстовый слой без внешних сервисов — то есть не упрётся в те же
стены, что YouTube/SPA-сайты.

**Что нужно:**
- Новая вкладка "PDF" в [add-text-tabs.tsx](../src/app/(app)/library/new/add-text-tabs.tsx),
  аналогично уже существующей "Фото" (`photo-import-form.tsx`) — загрузка
  файла, извлечение текста на клиенте (как tesseract.js для фото) или на
  сервере через новый server action.
- Ограничение на размер файла и число страниц (аналогично уже существующему
  `body.length > 200_000` в `createText`).
- Отсканированные PDF (картинки без текстового слоя) не вытащатся —
  предупреждение в UI, аналогично уже существующему "Не нашли текст на этом
  фото" в OCR-потоке.

**Сложность:** низкая-средняя. Основной риск — большие PDF (сотни страниц)
и время на извлечение в рамках лимита выполнения функции — тот же паттерн,
что мы уже применили для пагинации статей (time budget + cap по длине).

## 3. Рейтинг "сложных слов" в Статистике — СРЕДНИЙ приоритет, низкая сложность

**Что видно:** блок "Складні слова" — "За точністю (найгірші спочатку)"
(по точности, худшие сначала) — список слов, отсортированный по проценту
правильных ответов, худшие наверху.

**Почему это легко сделать у нас:** таблица `review_log` уже хранит
`grade` (0-3) на каждый ответ по каждой `flashcard_id` — этого достаточно,
чтобы посчитать процент "успешных" ответов (`grade >= 2`, например) на
карточку без миграций схемы.

**Что нужно:**
- В [progress/page.tsx](../src/app/(app)/progress/page.tsx) — новый запрос:
  сгруппировать `review_log` по `flashcard_id`, посчитать
  `count(grade >= 2) / count(*)` как точность, взять карточки с наименьшей
  точностью (и достаточным числом попыток — иначе одна "Не помню" в начале
  даёт 0% и попадает в топ несправедливо).
- Новый компонент-список (аналогично уже существующему `StatCard`), с
  переходом на карточку/её редактирование по тапу.

**Сложность:** низкая — один SQL-запрос (или агрегация на клиенте из уже
получаемых данных) плюс новый блок в существующем экране.

## 4. Готовые стартовые колоды по уровням (A1-B2, из частотных списков) — ВЫСОКИЙ приоритет, средняя-высокая сложность

**Что видно:** библиотека готовых колод "English Core A1 → Russian"
(500 карточек), A2 (800), B1 (888), B2 (1000) — построены на основе NGSL
(New General Service List — открытый, бесплатный частотный список слов
для изучающих язык, ровно то, что нужно по правилу "бесплатные инструменты").

**Почему это ценно:** сейчас у нового пользователя в Мозге пусто, пока он
сам не начнёт читать и сохранять слова — входной порог для тех, кто хочет
"просто начать учить слова" без чтения текстов. Готовые колоды дают
мгновенную ценность в день установки.

**Что нужно:**
- Собрать/найти открытый частотный список (NGSL 1.2 свободно доступен) для
  нужных языковых пар, разбить по уровням.
- Перевести headword → перевод (можно тем же MyMemory API, что уже
  используется для перевода в приложении, пакетно один раз при подготовке
  данных — не в рантайме).
- Новый экран "Библиотека готовых колод" в разделе Мозг — список,
  "Добавить в мои колоды" копирует карточки в `flashcards`/`decks`
  пользователя (с проставлением `language`, см. миграцию 0018).
- Нужно решить: эти стартовые колоды — часть бесплатного тарифа или
  premium-фича (влияет на `FREE_DECK_LIMIT`/`FREE_FLASHCARD_LIMIT` —
  добавление готовой колоды на 500 карточек мгновенно упрётся в лимит
  бесплatного тарифа в 50 карточек, нужно продуктовое решение: отдельный
  лимит на эти колоды, урезанный размер бесплатного набора, или premium-only).

**Сложность:** средняя-высокая — это не столько код, сколько контент
(подготовка словарных данных на каждую языковую пару) плюс продуктовое
решение по монетизации. Технически reuse существующих таблиц/экранов.

## 5. Переключатель направления изучения прямо на экране повторения — НИЗКИЙ приоритет, низкая сложность

**Что видно:** на экране повторения кнопки "ZH→RU" / "RU→ZH" видны сразу
над карточкой — переключить направление можно не заходя в настройки.

**Что у нас уже есть:** направление (`study_direction`) настраивается в
[Study Settings](../src/app/(app)/brain/settings/) и применяется во всех
трёх режимах повторения (см. `review-session.tsx`, `type-word-mode.tsx`,
`multiple-choice-mode.tsx` — это мы чинили во втором проходе аудита).
Не хватает только быстрого переключателя прямо в моменте повторения.

**Что нужно:** небольшой toggle-компонент в шапке
[review-mode-switcher.tsx](../src/app/(app)/brain/[deckId]/review/review-mode-switcher.tsx),
меняющий `study_direction` "на лету" (client state, не обязательно писать в
БД немедленно — можно применить только к текущей сессии, либо сохранять
как новый дефолт, это отдельное продуктовое решение).

**Сложность:** низкая.

## 6. Показывать итоговый интервал на кнопках оценки — НИЗКИЙ приоритет, низкая сложность

**Что видно:** кнопки оценки подписаны не только "Ещё раз/Сложно/Хорошо/
Легко", но и результатом — `<1d`, `1d`, `1d`, `1d` — сколько дней до
следующего показа при таком выборе.

**Почему стоит сделать:** прозрачность интервального повторения — известная
любимая деталь Anki-подобных приложений, снижает "магию" алгоритма.

**Что нужно:** в `review-session.tsx`/`type-word-mode.tsx` перед рендером
кнопок оценки — вызвать ту же функцию `reviewSrsState` из
[lib/srs.ts](../src/lib/srs.ts) для КАЖДОЙ из 4 оценок (не применяя,
только считая) и показать `intervalDays` на кнопке.

**Сложность:** низкая — функция расчёта интервала уже существует, нужно
только вызвать её 4 раза для предпросмотра вместо одного раза при сабмите.

## 8. Голосовой ввод при ручном добавлении слова — НИЗКИЙ приоритет, низкая сложность

**Что видно:** иконка микрофона в поле ввода слова при ручном добавлении
карточки — голосовой ввод вместо печати.

**Почему подходит по критерию "бесплатно":** Web Speech API
(`SpeechRecognition`) — встроен в браузер, бесплатен, без серверной части и
без API-ключей (в отличие от Whisper и т.п.). Работает не во всех браузерах
одинаково (Safari/iOS — с ограничениями), поэтому фича должна деградировать
незаметно, если API недоступен — показывать иконку микрофона только когда
`window.SpeechRecognition` реально существует.

**Что нужно:** в [add-word-modal.tsx](../src/app/(app)/notebook/add-word-modal.tsx)
и/или [add-card-form.tsx](../src/app/(app)/brain/[deckId]/add-card-form.tsx)
— кнопка микрофона рядом с полем ввода, использующая `SpeechRecognition`
для заполнения текстового поля голосом.

**Сложность:** низкая, но с оговоркой про неровную поддержку в браузерах
(нужно явно проверять доступность API и скрывать кнопку, если её нет).

## 9. Постраничный список слов в Тетради — НИЗКИЙ приоритет / вопрос на будущее

**Что видно:** "Сторінка 1 з 2" внизу списка слов в Зошите (при 58 записях
уже 2 страницы) — то есть у Lexpring относительно небольшой порог
пагинации.

**Что у нас сейчас:** [notebook/page.tsx](../src/app/(app)/notebook/page.tsx)
подгружает, судя по всему, весь список слов пользователя разом (без
пагинации/лимита) — при активном пользователе с тысячами слов это может
стать проблемой производительности рендера и загрузки страницы.

**Рекомендация:** не переделывать сейчас, но держать в уме как технический
долг — стоит добавить пагинацию или бесконечную прокрутку, когда реальные
пользователи начнут накапливать заметные объёмы словаря (условно, больше
пары сотен слов на аккаунт).

**Сложность:** средняя, если делать — но не срочно.

## 10. TikTok-импорт — под вопросом, не рекомендую сейчас

**Что видно:** вкладка "TikTok" в форме импорта, рядом с YouTube.

**Почему не советую делать сразу:** мы только что потратили значительное
время на диагностику YouTube-антибот-защиты (см.
[SECOND_PASS_AUDIT_FINDINGS.md](SECOND_PASS_AUDIT_FINDINGS.md) и переписку
по ScraperAPI) и выяснили, что даже с прокси YouTube отдаёт пустой контент
субтитров для анонимных запросов. TikTok контролируется тем же классом
антибот-защиты (возможно, даже более агрессивной — TikTok исторически
известен жёсткой защитой от скрапинга). Разумно сначала проверить, стоит ли
это той же борьбы, что и YouTube, прежде чем вкладывать время — на
практике многие TikTok-видео с "субтитрами" — это встроенные в кадр
(burned-in) титры, а не текстовая caption-дорожка, то есть их вообще нельзя
вытащить без OCR видео (ещё один пласт сложности).

**Рекомендация:** отложить, пока не решится (или не будет принято решение
не решать) YouTube-кейс — тот же класс проблемы, но, вероятно, ещё сложнее.

## Дополнительно найдено при повторном разборе

- **"Отправить карточку обратно в Тетрадь"** (кнопка "У зошит" на экране
  повторения) — перекрёстная связь между Мозгом и Тетрадью: если карточка
  из SRS-колоды оказалась слишком простой/ненужной для полноценного
  интервального повторения, можно понизить её до лёгкого режима практики
  без потери слова целиком (сейчас у нас только "Удалить").
- **Живой счётчик ответов во время сессии повторения** ("131 · 0 · 0" внизу
  экрана) — сколько карточек уже отвечено с каждой оценкой в ТЕКУЩЕЙ сессии,
  не за всё время. У нас `review-session.tsx` не показывает промежуточный
  итог сессии вообще.
- **Интерактивные тултипы на графиках Статистики** — на скрине при наведении
  на конкретный столбец показывается точное значение за день (у нас
  `line-chart.tsx` — просто SVG-полилиния без интерактивности, `hover`/
  `tap` не обрабатываются).
- **Счётчик записей в шапке Тетради** ("58 записів") — у нас в
  [notebook/page.tsx](../src/app/(app)/notebook/page.tsx) количество слов
  нигде явно не показано одной цифрой.
- **Избранное/звёздочка на слово** — отдельный флаг "важное слово", не
  привязанный к статусу изучения (new/learning/known) — можно закреплять
  сложные/нужные слова для быстрого доступа независимо от прогресса.

## Что НЕ делать (уже проверено на практике)

- Автоматическое построчное следование по всем страницам JS-рендерящихся
  сайтов (SPA вроде liteka.ru) без headless-браузера — даже сам Lexpring
  открыто предупреждает, что такие сайты не поддерживаются. Коллекции
  (идея №1) — правильный ответ на эту проблему, не более агрессивный парсинг.
- Полноценная интеграция yt-dlp/ffmpeg внутрь текущего Vercel-деплоя —
  требует другого рантайма (Python, диск, время выполнения) и не совместима
  с текущей serverless-архитектурой без отдельного сервиса.

## Рекомендованный порядок, если браться

1. Рейтинг сложных слов в статистике (№3) — почти бесплатно по трудозатратам,
   сразу заметная польза.
2. Коллекции для многочастевых текстов (№1) — решает реальную боль с
   книгами/сериями текстов, не борясь с антибот-защитами.
3. Импорт PDF (№2) — новый канал импорта без чужих ограничений.
4. Мелкие UX-детали в Мозге (№5, №6, №7) — можно сделать одним заходом,
   каждая по отдельности маленькая.
5. Готовые стартовые колоды (№4) — самая ценная для новых пользователей, но
   требует контентной подготовки и решения по монетизации до начала
   реализации.
6. Голосовой ввод (№8) — когда будет время, не приоритет.
